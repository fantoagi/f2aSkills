# fanto-article-generator

用于生成 AI 相关内容稿件的专用 Skill，支持三种严格分流的写作模式：

1. **模式 A：系列文章 / 番外篇** — fantoAGI 专栏风格，大白话、强比喻、痛点引入
2. **模式 B：行业快讯** — 接近机器之心/量子位，信息密度高、正式克制
3. **模式 C：AI 一线对话转述** — 公众号长文转述，记者转述感、大量直接引语

## 模式选择（写文章前必须先判断）

**默认：模式 A（系列文章 / 番外篇）。**

触发模式 A 的关键词：番外篇、系列文章、fanto 风格、沿用之前专栏风格

触发模式 B 的关键词：行业快讯、快讯稿、媒体稿、行业媒体风格、像机器之心、像量子位、科技媒体快讯

触发模式 C 的关键词：对话转述、访谈转述、播客整理、演讲整理、公众号转述、转译、对话全文、对话整理、转述文章

## 总原则

- 三种模式**严格分流**，不要混写调性。
- 默认输出中文。除非用户明确要求英文或双语，不输出英文正文。
- **英文源材料翻译工作流**：英文参考材料 → 先查阅 `references/ai-translation-guide.md` 按 3 阶段流程做精准翻译 → 再按目标模式改写。禁止跳过翻译步骤直接"提炼事实+重写"，禁止直译成生硬中文。
- 文章中引用的图片必须下载到本地后用相对路径引用，不要使用远程 URL（微信公众号发布时 wenyan 无法拉取 CDN 远程图片）。图片统一放在文章同目录下的 `images_<topic>/` 文件夹中。
- **Twitter/X 源材料强制规则**：X/Twitter 的图片嵌在 DOM 中，**纯文本方式（WebFetch/Jina/curl）拿不到图片 URL**。X/Twitter 源必须先走 CDP 浏览器获取完整内容（文本 + 图片）。流程：CDP `/new?url=` 打开推文 → `/eval` 提取 `document.querySelectorAll('img[src*="pbs.twimg.com/media"]')` → 下载图片到 `images_<topic>/` → 同步记录每张图前后的文字上下文用于排版。
- **Twitter/X 配图 GIF 检测**：检查 DOM 中是否有 `tweet_video_thumb` 或 `tweet_video` 标签，如有则下载 MP4 并用 OpenCV + PIL 转换为 GIF（~20 帧、宽 900px、PIL quality 70、100ms/帧、≤5MB）。环境无 cv2 时先 `pip install opencv-python`。

## 模式 A：系列文章 / 番外篇

### 核心调性（压缩）

1. **大白话 + 强比喻**：烧烤摊上给不懂技术的业务老板讲技术。全文围绕**一个主比喻**展开，用生活中极常见的事物映射复杂概念。
2. **痛点引入开头**：用读者工作中抓狂/尴尬/痛苦的场景引入，不抛概念、不写"本文将介绍……"。
3. **通俗不失真**：可以降术语密度，不能篡改因果关系。容易误解的概念补一句"它像什么，但不等于什么"。
4. **短句 + 粗体 + 引用块**：句子短平快，用 `**` 和 `>` 突出核心结论，不写技术说明书。

### 写作骨架

- **标题**：`番外篇 XX｜痛点/反差现象标题？（谈谈专业概念：[核心术语]）`
- **章节**：开篇(痛点共鸣) → 一、大白话定义 → 二、它是怎么转起来的(优先 Mermaid 图) → 三、为什么重要 → 四、边界/误区/代价 → 五、什么时候该用/别乱用 → 结尾(一句金句)

### 术语铁律

全文先锁定 **1 个主术语**，别称 ≤2 个，同一主体不要来回换名字。标题/开篇/小节标题/结尾对齐。

### 不可妥协

- 不堆术语、不写教科书腔、不写"本文将介绍……"
- 全文围绕一个主比喻，不来回切换零散比喻
- 必须讲边界和代价，不能只讲优点

> 完整写作调性(6点)、完整SOP(7步)、Mermaid详细规则(6条)、禁忌清单(9条)、自检清单(9条)、系列连续性要求、完整模板 → `references/mode-a.md`

## 模式 B：行业快讯

### 核心调性（压缩）

1. **专业克制，信息密度高**：句子干净，信息集中，事实句和判断句为主，不写聊天体。
2. **直接进入事实**：开头直接交代"发布了什么、升级了什么、为什么值得关注"，不从场景或人物代入切入。
3. **媒体快讯感**：核心是快速传递重点，不是概念启蒙，也不是专栏杂谈。

### 写作骨架

- **标题**：科技媒体快讯标题，直接写主体+事件+关键信息。示例：`DeepSeek-V4 发布并开源：Agent、推理与 1M 上下文同步升级`。不用 `番外篇 XX｜` 格式。
- **章节**：开头(一句话交代发布事实) → 一、核心升级点(2-4个) → 二、行业位置与对标 → 三、接入与使用方式 → 结尾(一句凝练判断)

### 不可妥协

- 不写大白话解释文，不用强比喻做文章主结构
- 不用"你一定遇到过""很多老板第一次听到"等口语开头
- 不用模糊发虚词（"区间""一档""口径"等），不写拖沓过渡句

> 完整写作调性(5点)、完整SOP(5步)、标题详细规则及示例、禁忌清单(7条)、自检清单(6条)、完整模板 → `references/mode-b.md`

## 模式 C：AI 一线对话转述

### 核心调性（压缩）

1. **记者转述感**：像科技记者在整理一场重要对话——有信息量有温度，不是专栏杂谈。角色是"转述者"，不是"评论员"也不是"翻译机器"。
2. **大量直接引语**：保留 speaker 原话质感。`"80 倍太疯狂了，是真的扛不住"` 比 `"Dario 表示增速难以承受"` 有力十倍。关键句用粗体强调。
3. **场景化叙事**：每章从对话中的自然转折切入，不用"关于 X 问题，Y 认为……"。
4. **中文口语化但正式**：不是翻译腔也不是烧烤摊大白话。目标语感——"一个表达很好的科技记者在跟你讲他刚听到的一场对话"。
5. **张力驱动**：全文围绕一个核心矛盾展开（速度 vs 安全、解放 vs 颠覆）。动笔前先想清楚"这一篇的核心张力是什么"。

### 写作骨架

- **标题**：`核心人物身份 + 冒号 + 最抓眼球的 2-3 个关键词/金句`
- **导语三段式**：[引用式概括 `>`] → [时间地点人物上下文 1-2 句] → [话题弧线 + 过渡句]
- **正文 8-10 节**：每节 `## 中文数字序号、观点金句标题`，从场景/问题引入 → 直接引语+解释 → 数据/细节展开
- **结尾两段式**：[总结升华回到核心张力] → [来源标注行：`*本文内容全部来源于 [来源名] [场合/日期]"[环节名/标题]"，[链接类型]：[URL]。*`]

### 章节类型速查

必选：人物色彩章、核心数据章、深度展开章×2-3。可选：概念定义章、宏大叙事章、展望预测章、收尾缓冲章。**单人长文变体**：跳过人物色彩章，以核心论点和深度展开章为主体。完整菜单及选用规则见 `references/mode-c.md`。

### 硬性质控（最高优先级，写完逐条对照）

1. **来源保真**：文章每句话都能在源材料中找到对应。不扩充、不联想、不加分析评论。检查方法：逐句在源材料中找对应，找不到的删掉。
2. **中文表达自然**：对照 `references/ai-translation-guide.md` 自查清单检查翻译腔、被动语态直译、长定语堆叠、中文常见坑（"倍"用于降、多余的"层面""关于……的问题""在……的过程中"等）。
3. **配图位置对齐原文**：每张图放在源材料中对应的内容段落后，不凭感觉重排。获取配图时同步提取位置上下文。

### 英文源材料翻译流程

英文播客/访谈/转录/长文 → 先按 `references/ai-translation-guide.md` 的 3 阶段流程做精准翻译 → 再按模式 C 骨架和调性改写为转述文章 → 完成后对照翻译指南自检清单逐条检查。禁止跳过翻译步骤。

> 完整写作调性(6点)、文章骨架详解(标题/导语/正文/结尾完整公式)、章节类型菜单(7种角色及选用规则)、硬性质控规则详解(3条及检查方法)、完整SOP(7步含X/Twitter前置检查)、禁忌清单(8条)、自检清单(6条)、完整模板 → `references/mode-c.md`

## 封面图生成

### 硬性约束

- 比例 2.35:1，推荐 940×400
- 背景浅色（`#f8fafc` / `#fafbfc` 系），不用深色
- 先写 SVG 源文件，再渲染为 PNG，frontmatter 引用 PNG

### 渲染

**推荐**：调用本 skill 自带脚本，一条命令出 PNG：

```bash
python scripts/render_cover.py <cover.svg> [cover.png]
```

**前置依赖**：Chrome 必须已启动且带 `--remote-debugging-port=9222 --remote-allow-origins=*`。脚本自动探测并启动 Chrome。

**降级**：若脚本不可用，依次尝试 `cairosvg` → 手动 CDP WebSocket 链路（详见 `references/cover-generation.md`）。

### 自检要点

- 比例 2.35:1？元素无重叠？各层文字 ≥10px 等效字号？
- **PNG 文件必须实际存在且 >0 字节**，SVG 写完不算完成。

> 完整设计原则(5点)、配色规则、CDP环境搭建详解(启动命令+约束+依赖)、生成流程详解(3级优先级+4个手动CDP陷阱)、完整自检清单(5条) → `references/cover-generation.md`

## Frontmatter 与文件命名

每篇文章开头必须包含（不可遗漏）：

```markdown
---
title: 文章标题
cover: ./board2_render.png
---

# 文章标题
```

文件命名约定：系列文章 `fanto_article_<topic>.md` | 行业快讯 `fanto_news_<topic>.md` | 对话转述 `fanto_talk_<topic>.md`

`frontmatter.title`、正文 `# 一级标题`、文件主题三者必须一致。

## Standard Invocation Pattern

当需要执行写文章任务时：

1. 读取本 SKILL.md 的规范
2. 判断当前任务属于模式 A/B/C
3. **若源材料为英文**：先查阅 `references/ai-translation-guide.md`，按翻译指南做精准翻译，再按目标模式改写
4. **若源材料来自 X/Twitter 且为模式 C**：先走 CDP 浏览器提取文本和图片（纯文本方式禁止用于 X/Twitter 源材料）
5. 按目标模式撰写中文正文
6. **优先路径**：用 `Write` 工具写本地 Markdown 文件（绝对路径，带 frontmatter）
7. **降级路径**：若 `Write` 不可用，直接输出完整 Markdown 成品，外层用四个反引号包裹
8. 告知用户文件已生成或正文可直接进入下一步

## 调用示例

### 示例 1：模式 A（系列文章）

用户："帮我写一篇关于 Agent 幻觉的番外篇。"
→ 识别模式 A → 锁定主术语"Agent 幻觉" → 确定主比喻 → 痛点引入开头 → 大白话展开 → 配 Mermaid 图（如涉及流程）→ 输出 `fanto_article_agent_hallucination.md`

### 示例 2：模式 B（英文源材料）

用户："基于这篇英文发布稿，写一篇行业快讯，风格像量子位。"
→ 识别模式 B → 查阅 `references/ai-translation-guide.md` → 精准翻译英文发布稿 → 按快讯结构改写 → 输出 `fanto_news_ai_release.md`

### 示例 3：模式 C（英文播客转录）

用户："基于这篇播客转录，写一篇公众号对话转述文章，中文输出。"
→ 识别模式 C → 查阅 `references/ai-translation-guide.md` → 精准翻译转录稿 → 通读提取核心观点/引语/数据/细节 → 确定核心张力 → 选配章节类型 → 按转述骨架撰写 → 三条约法自检 → 输出 `fanto_talk_speaker_name.md`
