# 模式 B：行业快讯 — 完整规范

> 由 `SKILL.md` 按需加载。英文源材料必须先读完 `references/ai-translation-guide.md` 做精准翻译后再按本模式改写。

## 🎯 核心写作调性（必须严格遵守）

行业快讯模式必须采用更接近科技媒体快讯稿的表达方式：

1. **专业、克制、信息密度高**：句子要干净，信息要集中，不写聊天体，不写情绪化铺垫。
2. **直接进入事实与判断**：开头直接交代"发布了什么、升级了什么、为什么值得关注"，不要从抓狂场景或人物代入切入。
3. **像媒体快讯，不像专栏杂谈**：核心是快速传递重点，而不是做概念启蒙。
4. **以事实句和判断句为主**：多写"发布了什么、达到了什么、支持什么、意味着什么"，少写松散的解释性过渡。
5. **默认中文输出**：即使参考材料为英文，最终正文也默认输出中文行业稿。

## 📜 行业快讯写作 SOP

1. **先抓新闻核心**：明确本次发布、更新或行业变化最值得关注的 2-4 个点。
2. **先定信息优先级**：优先回答：
   - 发布了什么
   - 核心能力或变化是什么
   - 处在什么行业位置
   - 用户或开发者如何使用 / 接入
3. **按快讯结构撰写**：标题已由 SKILL.md 阶段三的标题阻断点完成（按 `references/shared/title-workflow.md` 5 步法生成 + 质控 7 条），确认标题符合模式 B 的"主体+事件+关键信息"格式约束，不用 `番外篇` 前缀。
   - **开头（3 种策略，写前选择，不默认一种）**：
     - **策略 A — 事实直给**：一句话交代发布主体 + 事件 + 最关键的 1 个变化。适合重要发布/重磅产品。示例：`6 月 16 日，Anthropic 发布了 Claude 5，核心变化只有一句话：Agent 能力从"辅助执行"升级为"自主完成"。`
     - **策略 B — 数据冲击**：用一个具体数字或对比数据切入，再交代背景。适合有 benchmark 数据/性能跃升的发布。示例：`在最新发布的 SWE-bench Verified 评测中，Claude 5 的得分从 49% 跳到了 72%——不是渐进提升，是跳档。`
     - **策略 C — 行业争议切入**：先点出一个行业争论或矛盾，再用本次发布作为回应或新变数。适合有竞品对比/路线分歧的事件。示例：`"开源模型正在追平闭源"是过去半年的主流叙事。Claude 5 的发布让这个叙事需要重写。`
   - **第一部分**：核心升级点
   - **第二部分**：行业定位 / 对标关系
   - **第三部分**：接入与使用方式。**本章结尾必须加一行"行动指向"**：`> 🎯 如果你在 [X 场景]，你现在应该 [Y 具体行动]。`（如"如果你在评估 Agent 框架，Claude 5 的 Computer Use 新 API 值得立刻跑一次 benchmark"）——让扫读的忙人知道"跟我有什么关系"。
   - **结尾**：
     - 一行**实质级别标注**：`📊 实质级别：渐进优化 / 重要升级 / 拐点级变化`
     - 一个**历史对比锚点**：上次同等量级的更新是什么（如"上次同等量级的 Agent 能力更新是 2024 年 6 月的 Claude Computer Use"）
     - 一句**有立场的判断**：不是"进一步拉近了 X 和 Y 的差距"这种正确废话，而是"这意味着……"的具体判断
4. **控制篇幅**：优先压缩冗余解释，保证读者能快速扫完重点。
5. **生成本地文件**：使用 `Write` 工具，在用户当前工作目录下创建 Markdown 文件。

## 🧭 行业快讯标题规则

- 不使用 `番外篇 XX｜` 这类专栏标题格式。
- 标题要像科技媒体快讯：
  - 直接写主体 + 事件 + 关键信息
  - 示例：`DeepSeek-V4 发布并开源：Agent、推理与 1M 上下文同步升级`
  - 示例：`OpenAI 发布新模型：多模态能力首次进入实时语音产品`
- 标题可以有张力，但不能浮夸，更不能像营销号。
- 标题不只要写"主体+事件+关键信息"，还要回答"这个事件意味着什么"。
  差：`DeepSeek-V4 发布并开源：Agent、推理与 1M 上下文同步升级`
  好：`DeepSeek-V4 开源：Agent 和推理同步升级，开源模型的 GPT-5 时刻还有多远`

> 标题生成同步参考 `references/shared/title-workflow.md`：模式 B 主推公式 2（趋势+反常识），保持克制基调，增加量化钩子。生成标题时按 5 步法打磨，不破坏快讯的专业克制感。

## 🚫 行业快讯禁忌

- 不要写成大白话解释文。
- 不要使用强比喻作为主结构。
- 不要使用"你一定遇到过""很多老板第一次听到"这类口语开头。
- 不要写成"本文将介绍"的教科书腔。
- 不要写成产品宣传稿。
- 不要使用模糊、发虚的词，比如"区间""一档""口径""比较的区间"这类表达，除非是在转述原句且无法替换。
- 不要出现拖沓的过渡句，比如"这一部分其实可以很快看完""也就是说大家都知道"。
- 不要在标题里列举功能而非传递信号。
- 不要写"进一步拉近""持续缩小"这类无信息量的判断句。

## ✅ 行业快讯自检

写完后必须检查：

1. 开头是否直接进入发布事实，而不是场景铺垫。
2. 是否优先写清"升级点 / 对标位置 / 使用方式"。
3. 是否保持正式、克制，而非聊天体或宣传腔。
4. 是否删掉了含混、发虚、绕弯的表达。
5. 即使参考资料是英文，正文是否仍然默认输出为中文。
6. 整体是否更像科技媒体快讯，而不是专栏解释文。

```markdown
# 你的行业快讯标题

[一句话交代发布事实和最关键结论]

---

## 一、核心升级点

[写清本次发布最重要的 2-4 个变化]

---

## 二、行业位置与对标关系

[写清相对开源和头部闭源模型的定位]

---

## 三、接入与使用方式

[写清使用入口、API、迁移信息、关键参数]

---

## 四、结语

📊 实质级别：[渐进优化 / 重要升级 / 拐点级变化]
对比锚点：[上次同等量级更新]

> [一句有立场的判断——不是正确废话，是"这意味着……"的具体判断]
```
