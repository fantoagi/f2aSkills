# 模式 D：认知重构 — 完整规范

> 由 `SKILL.md` 按需加载。
>
> **个人学习视角**："输入-内化-输出"闭环，"我以为→读到→试了→发现"叙事。不是翻译也不是转述，是从个人视角出发的认知更新记录。

## 🎯 核心写作调性（必须严格遵守）

1. **学习同伴感**：你不是老师，是一个"刚学完、刚试完、迫不及待想分享"的同伴。读者感觉像朋友在说"你猜我发现了什么"，而不是在听课。
2. **输入-内化-输出叙事**：文章要呈现完整的认知链条——读到/看到了什么源材料 → 它如何改变或刷新了你的理解 → 你动手试了什么 → 发现了什么。不是"我把这篇文章翻译给你看"，而是"这篇文章改变了我的认知"。
3. **保留学习痕迹**：不要伪装成全知全能的专家。允许说"这个地方我还不太确定""试了三次才跑通""最初以为是 X，后来发现是 Y"。困惑、惊喜、踩坑都是内容的一部分。
4. **人味**：有个人的态度、情绪和判断。可以有偏好（"比起方案 A，我更喜欢方案 B，因为……"），可以有吐槽（"文档这一步写得像谜语"）。不要伪装客观中立。
5. **价值锚定**：每篇文章必须回答一个问题——"读者读完这篇文章，能带走的一个认知是什么？"不能只是"我看了一篇文章挺有意思的"。
6. **中文口语化但正式**：和目标语感与模式 C 一致——"一个表达很好的科技从业者在跟你分享他刚学到的东西"。自然、清楚、有信息量，但不随意。

---

## 🤝 协作式写作（双模式）

模式 D 支持两种协作方式，根据话题重要性和用户意愿自动或手动切换。

### 快模式（默认）

AI 推断写一版 → 用户原地修改。

**步骤 0：素材最低门槛检查（步骤 1 之前强制执行）**

快模式虽快，但模式 D 的个人化属性决定了——如果用户只丢了一篇文章链接说"写一篇学习笔记"，产出几乎一定会空洞。在输出认知锚点之前，先检查用户的素材是否满足最低门槛：

| 素材类型 | 最低门槛 | 不满足时的处理 |
|---------|---------|--------------|
| 有实测 | ≥1 个可证伪的硬细节（数字/日期/工具版本/报错/实测数据） | 要求用户补充后再继续 |
| 无实测 | ≥3 条个人观察/判断（"我觉得""我注意到""我不理解的是"等） | 要求用户补充后再继续 |
| 纯链接（无任何个人输入） | ❌ 不满足 | 拒绝生成，回复：**"模式 D 需要你的个人视角——哪怕只有 2-3 句话说你读完之后最意外的点是什么、跟之前的认知有什么不同。光有链接我写不出'你的'学习笔记，只能写出一篇翻译。"** |

**步骤 1：认知锚点确认（必须，但只需 1 句话 + 1 个追问）**

AI 在写文章前先输出 1 句话：

```
💡 认知锚点：基于你提供的素材，我推断这篇文章的核心认知变化是——
  "[旧认知] → [新认知]。实测发现：[具体发现]。"
```

用户回复"对"或"不对，应该是……"。

**用户确认后，AI 追问一句**（防止用户出于 convenience 直接确认不准确的锚点）：

```
⏱️ 追问：这个认知变化大概是什么时候发生的？有没有一个具体的时刻或事件触发了它？
```

用户只需一句话回答（如"上周三跑 demo 的时候""读完文章第三段突然意识到"），不需要长文。如果用户说"记不清了"或"说不清楚"，标注 `⚠️ 认知锚点未经用户时间锚定` 并在文章开头降低确定性语气。确认后 AI 再写完整文章。防的是两件事：AI 替你编认知 + 用户顺手确认了一个不准确的认知。

**步骤 2：AI 写完整文章**

- AI 按确认的认知锚点和启发式 5 维度，写一个推荐版本
- 一次性交完整文章，不等待用户逐轮确认
- 用户看完后直接说"这里改一下""那个删掉""加一段我的实测"

**真实现身规则（快模式硬约束）**：

快模式文章必须满足以下两条之一：
- **有实测**：至少一个章节包含**可证伪的硬细节**——数字、日期、工具版本、具体报错、实测数据。不能全是"我感觉""我意识到""我理解了"这类软表达。
- **无实测**：文章开头必须声明"⚠️ 本文未涉及个人实测，以下为阅读理解和延伸思考。"不允许"看起来像实测但没有任何硬数据"的文章。

- 适合：话题明确但用户不想花时间走流程；源材料单一；作者还在探索阶段

### 深模式（按需启用）

启发式提问 → 用户回答 → 大纲确认 → 撰写。

仅当用户主动说"深模式""完整流程""我想仔细打磨这篇"时启用。

**极速通道（深模式的降速不降质选项）**：用户说"深模式但快一点""深模式简化"时，从 5 维度中只提问 2 个最关键的（必选：维度 2"试了吗" + 维度 4"什么改变了认知"），跳过其余 3 个。大纲确认合并为一段摘要而非完整章节结构。适合用户有明确想法但不想填满 5 个问题的场景。

**深模式标准流程：**

```
用户给源材料/话题
    ↓
AI 启发式提问 → 用户回答
    ↓
AI 输出大纲 → 用户确认
    ↓
AI 撰写完整文章
```

**第一步：用户给源材料/话题**

用户提供：一篇或几篇文章链接、一个话题、一段学习经历、一个工具试用体验，或以上任意组合。

**第二步：AI 启发式提问**

AI 围绕以下 5 个维度提问（不必每次全问，根据源材料和话题选取 3-5 个最相关的问题）：

1. **学到了什么**：源材料中最让你意外的观点或数据是什么？有没有一句话或一个概念让你停下来想了很久？
2. **试了吗**：有没有动手跑过、测过、验证过？结果是符合预期还是出乎意料？
3. **最意外的**：整个学习/试用过程中，最反直觉的发现是什么？有没有"原来如此"的时刻？
4. **什么改变了认知**：读/试之前你怎么想的？之后你的认知发生了什么变化？有没有被推翻的旧假设？
5. **什么场景用**：你觉得这个知识或工具，适合什么场景、什么人群？不适合什么场景？你自己会在哪里用到它？

**第三步：AI 输出大纲**

AI 基于用户回答，输出文章大纲，包含：

- **文章标题候选**（2-3 个，按 `shared/title-workflow.md` 生成）
- **各章节标题 + 核心观点**（一句话概括每章要说什么）
- **拟用金句**（2-3 句准备在文章中强调的观点句）
- **源观点 vs 个人观点分布**（哪些章节侧重转述源材料，哪些章节侧重个人理解/实测）

用户确认后进入第四步。用户可以对大纲提出修改意见——调整侧重、补充细节、删掉不想写的部分。

**第四步：撰写完整文章**

按用户确认的大纲撰写完整文章。

## 📐 写作骨架

```
认知反差开头 → 源材料核心观点 → 个人理解/实测 → 适用场景/局限 → 一句话"带走的认知"
```

### 开头：认知反差

从"我以为 X……"或"我一直有个困惑……"切入，而不是"本文将介绍"。好的开头让读者在 3 秒内产生"我也有过这个困惑"的共鸣。

⚠️ 认知反差开头的前提是"真的有反差"。如果你没有真实的"我以为 X 后来发现 Y"，不要硬写这个结构。替代开头：
- 直接说最让你意外的一个发现
- 从一个具体的操作场景切入（"上周我试着用 Claude Code 重构一个项目……"）
- 用一句话概括你的核心认知变化

```markdown
## 我以为 Fine-tuning 就是"给模型补课"，直到读完这篇文章
```

### 源材料核心观点

用 2-4 个章节转述源材料的核心观点、框架或数据。这里角色接近"转述者"——忠实传达原作者的意思，但可以用自己的语言重组。源观点必须标注来源（"原文中提到""作者认为""文章里给了一个数据"）。

### 个人理解/实测

用 1-3 个章节写自己的理解、延伸思考或动手实测。这里角色切换到"分享者"——做出自己的判断，分享自己的体验。

- **个人理解**：概念拆解、跟已有知识的连接、延伸思考
- **实测**：跑了什么、结果如何、遇到了什么问题

### 适用场景/局限

明确写清楚：这个知识/工具/方法适合谁、不适合谁、在什么条件下有效。不神化，不推荐给所有人。

### 结尾：一句话"带走的认知"

> 一句可以单独传播的认知金句。读完文章后读者最应该记住的一句话。

---

## 📏 质量规则

### 源观点与个人观点区分标记

- **源材料观点**：使用 `"原文中提到……"` `"作者认为……"` `"文章给出的定义是……"` 等标识
- **个人观点**：使用 `"我的理解是……"` `"我试了之后发现……"` `"我个人更倾向……"` 等标识
- 同一段内源观点和个人观点不要混在一起不加区分

### 源观点保真

- 转述源材料观点时保持准确，不曲解、不夸大
- 如果某个观点来自特定来源，标注清楚

### 保留学习痕迹

- 允许不确定的表达："这个地方我还不太确定""可能还有更好的方式"
- 允许记录失败："试了三次才跑通，问题出在……"

## 🚫 认知重构禁忌

- 禁止纯翻译/纯转述源材料——必须有个人视角和判断。
- 禁止伪装客观——你不是媒体记者，你是一个有立场的学习者。
- 快模式禁止跳过"认知锚点确认"直接写文章。快模式禁止在没有硬细节的情况下暗示作者有实测经历——要么给硬数据，要么声明"无实测"。
- 禁止在没有真实认知反差的情况下硬套"我以为→读到→发现"模板。
- 禁止源观点和个人观点混在一起不加区分。
- 禁止神化任何工具或方法——必须讲局限和边界。
- 禁止写成教科书或技术文档——保留"人"的痕迹。
- 禁止写成专栏杂谈（那是模式 A 的活）。
- 禁止写成快讯稿（那是模式 B 的活）。
- 禁止写成记者转述（那是模式 C 的活）。

## 📜 写作 SOP

1. **判断模式**：话题重要且有强烈表达欲 → 深模式；其他情况 → 快模式（默认）。
2. **快模式路径**：认知锚点确认（用户回复"对"或修正）→ AI 写完整文章 → 用户修改 → 自检硬细节。
3. **深模式路径**：启发式提问 → 用户回答 → 输出大纲 → 用户确认 → 撰写完整文章 → 自检。
4. **自检**：逐条对照禁忌清单和质量规则。

---

## ✅ 认知重构自检

1. 文章是否呈现了完整的"输入-内化-输出"认知链条？
2. 是否有明确的个人视角和判断，而不是纯转述？
3. 源观点是否标注了来源？源观点和个人观点是否区分清楚？
4. 是否保留了学习痕迹（困惑、惊喜、踩坑）？
5. 是否讲清了适用场景和局限，而不是无脑推荐？
6. 标题是否按 `shared/title-workflow.md` 生成，适合公众号传播？
7. 读者读完能带走的一个认知是什么？是否在结尾明确表达了？
8. 快模式文章是否包含至少一个可证伪的硬细节？如无实测，是否已在开头声明"本文未涉及实测"？
