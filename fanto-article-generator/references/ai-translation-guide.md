# 🤖 AI 行业文章翻译规范（通用受众版）

> **适用范围**：AI 行业深度分析、技术战略解读、产品发布、投资逻辑、架构演进等英文内容中译
> **目标受众**：泛 AI 人群（从业者/产品经理/创业者/投资者/技术爱好者），非纯硬核研发向
> **核心目标**：**完整精确还原原文信息密度与逻辑链条**，兼顾中文阅读流畅度；对行业固化术语采用"保留英文/标准中文"混合策略，杜绝强行翻译与信息稀释
> **版本**：V1.0-Stable | **语言方向**：EN → ZH | **最后更新**：2026-05

---

## 🎯 一、核心翻译原则

### 1. 精准还原优先（Fidelity First）
- **不增删、不概括、不主观润色**：严格对应原文段落结构、逻辑递进与信息密度。
- **技术细节零妥协**：架构设计、数据流向、模型行为、实验结论等必须 100% 准确传递。
- **语气与立场保持一致**：原文的批判性、前瞻性或克制表述需完整保留，不中性化或情绪化。

### 2. 普适可读导向（General Audience Ready）
- 面向泛 AI 读者，技术概念需**准确但易懂**。避免学术化长句，可用符合中文习惯的短句重组，但绝不改变原意。
- 复杂机制（如 RAG 检索链、Agent 规划循环）若原文已解释，译文需保持同等解释粒度；若原文默认读者具备基础认知，译文不额外补充背景。

### 3. 术语双语策略（Hybrid Terminology）
- **业内高度共识的英文词直接保留**：不强行翻译已固化且广泛使用的英文名词/缩写。
- **首次出现可加注**：采用 `英文（中文释义）` 或 `中文（英文）` 格式，后续统一使用最简形式。
- **语境决定译法**：同一词在不同上下文（如 `Memory` 在模型上下文 vs 数据库缓存）需采用对应准确表述。

## 🔤 二、AI 术语处理规则（重点）

### 📌 直接保留英文（泛读者已熟知）
> 全文统一保留，不加注，除非原文首次出现时已有解释

| 术语 | 说明 |
|:---|:---|
| `LLM` | 大语言模型，中文圈已完全通用 |
| `RAG` | 检索增强生成，保留缩写更简洁专业 |
| `Agent` | 智能体/代理，保留英文最符合行业习惯 |
| `Memory` | 对话记忆/长期记忆/向量存储，依语境理解 |
| `Skills` | Agent 技能/工具调用能力 |
| `Prompt` | 提示词/指令，保留英文更自然 |
| `Context / Context Window` | 上下文/上下文窗口，技术语境保留 |
| `Token` | 计费/长度单位，不译 |
| `MCP` | Model Context Protocol，协议名保留 |
| `API / GUI / CLI` | 标准技术缩写，保留 |
| `Zero-shot / Few-shot` | 提示工程标准术语 |
| `Fine-tuning` | 可保留或译为"微调"，首次出现建议中英对照 |

### 📌 首次中英对照，后续简化
> 首次出现标注，后文按需使用最简形式

| 英文 | 建议格式 | 后续用法 |
|:---|:---|:---|
| `Alignment` | `Alignment（对齐）` | 对齐 |
| `Orchestration` | `Orchestration（编排）` | 编排 |
| `Grounding` | `Grounding（事实锚定）` | 事实锚定 |
| `Hallucination` | `Hallucination（幻觉）` | 幻觉 |
| `Pipeline` | `Pipeline（流水线）` | 流水线/工作流 |

### 📌 强制标准中文（有明确行业共识）
> 统一采用中文技术社区译法，避免歧义

| 英文 | 标准译法 | 备注 |
|:---|:---|:---|
| `Training / Inference` | 训练 / 推理 | 固定搭配 |
| `Embedding` | 嵌入 / 向量表示 | 依语境选择 |
| `Retrieval` | 检索 | 不译"召回"除非特指召回率 |
| `Generation` | 生成 | 不译"产生" |
| `Reasoning` | 推理 / 逻辑推导 | 依语境选择 |
| `Planning` | 规划 / 任务规划 | Agent 语境用"规划" |
| `Tool Calling` | 工具调用 | 不译"函数调用"除非特指 Function Calling |

### 📌 多义词按语境区分
> 结合上下文选择精确译法，避免一刀切

| 英文 | 语境 1 | 语境 2 | 语境 3 |
|:---|:---|:---|:---|
| `Context` | 对话/提示词上下文 | 业务语境/市场环境 | 技术上下文窗口 |
| `Model` | AI 模型 | 架构范式/方法论 | 商业模型（需谨慎区分） |
| `Workflow` | Agent 执行链 | 业务流程/审批流 | 数据处理流水线 |
| `State` | 模型状态/对话状态 | 系统状态/应用状态 | 州（地理，需区分） |

### 📌 禁止强行翻译
> 若中文表述会引发歧义、冗长或偏离原意，保留英文

| 原文 | ❌ 错误译法 | ✅ 推荐处理 |
|:---|:---|:---|
| `Agentic workflow` | "智能体代理工作流" | `Agentic 工作流` 或保留英文 |
| `Computer-use Agent` | "计算机使用智能体" | `Computer-use Agent` 或 `界面操作型 Agent` |
| `Data exhaust` | "数据尾气" | `过程痕迹数据` 或保留英文+加注 |
| `System of Record` | "系统记录" | `权威记录系统（System of Record）` |
| `Headless` | "无头" | `解耦前端架构（Headless）` 或保留+加注 |

> 💡 **核心底线**：翻译是为了降低理解门槛，不是改变行业语言习惯。当英文术语已成为中文 AI 圈日常表达时，**保留即是最精准的翻译**。

## 🔄 三、标准化工作流

### 🟦 阶段 1：预处理（5 分钟）
- 通读全文，用高亮标出核心 AI 术语（Agent, RAG, Memory, Skills, Context, LLM, MCP 等）
- 对照「术语处理规则」确定保留词与标准译法
- 识别长难句逻辑链（因果/递进/转折），规划中文重组方式
- 标记原文图表/代码/引用块，保留占位符 `[FIGURE]`/`[CODE]`
- 判断文章基调：技术架构/商业战略/产品发布/投资分析，调整译法颗粒度

### 🟨 阶段 2：翻译执行（逐段对齐）
**执行原则：**
1. 段落级对应：不合并、不拆分原文段落，保持信息节奏一致
2. 逻辑显式化：英文隐含的 because/which/while 用中文`因/故/而/尽管`显式连接
3. 技术保真：模型能力、数据流向、架构边界等描述严格逐字校准
4. 可读性优化：被动转主动，长句拆为短句，删除冗余`被/进行/作出`
5. 术语一致：全文同一概念译法/保留形式绝对统一

**遇到不确定时：**
- 术语：查阅主流 AI 媒体（机器之心/量子位/InfoQ）或官方中文文档
- 句式：参考同类高质量译文，优先保证技术准确
- 语境：若原文为战略/商业分析，术语可适当口语化；若为技术架构，保持严谨
- 保留词：当犹豫是否翻译时，默认保留英文+首次加注

### 🟥 阶段 3：后校验（质量门禁）
- 术语一致性：全文 Agent/RAG/Memory/LLM 等保留词或译法是否统一？
- 无强行翻译：是否保留了业内固化英文词？是否避免了生造词？
- 技术准确性：模型行为、数据流向、架构逻辑是否与原文 100% 对齐？
- 逻辑完整性：英文长句的因果/条件/修饰关系是否在中文中清晰保留？
- 受众适配：泛 AI 读者能否无障碍理解技术机制与商业判断？
- 无翻译腔：彻底清理冗余被动词、西式语序、过度直译短语
- 格式对齐：标题层级、列表、引用块、加粗/斜体与原文严格一致
- 加注规范：首次出现的保留词是否已按`英文（中文释义）`格式处理？

- [ ] 标题、列表、引用、加粗/斜体与原文严格对齐

## 📝 实战示例：以 Seema Amble 文章片段为例

### 原文片段
> "Agents are disrupting this model because they don't need to read and write data through a UI, which has catalyzed a wave of tools and workarounds that completely bypass the interface."

### ❌ 易错译法
> "Agents 正在颠覆这个模型。它们不需要通过 UI 来读写数据，这催生了一波完全绕过界面的工具和变通方案。"

### ✅ 推荐译法
> "Agent 正颠覆这一模式：因其无需通过 UI 读写数据，直接催生了一批完全绕过界面层的工具与变通方案。"

### 🔍 优化点解析
| 优化项 | 说明 |
|:---|:---|
| `Agents` → `Agent` | 中文行业习惯单数泛指，不译"智能体们" |
| `because` → `：因其` | 用中文因果连接词显式保留逻辑链 |
| `which has catalyzed` → `直接催生了` | 维持`which`的驱动关系，避免拆句稀释 |
| `completely bypass` → `完全绕过` | 准确传递"彻底规避"的语气强度 |
| 保留 `UI` / `Agent` | 业内固化英文词，不强行汉化 |

> 💡 **翻译心法**
> AI 行业内容的翻译，**精准不是字字对应，而是行业语言习惯与信息密度的双重还原**。
>
> 面对泛读者：
> - 不降低技术准确性，不堆砌学术黑话
> - 不强行汉化固化英文词，不制造理解摩擦
> - 用中文的流畅承载英文的严谨
>
> 每完成一段自问：
> *"这段译文是否让中文读者获得了与英文读者完全相同的技术认知与商业判断？"*
>
> 若答案是肯定的，则翻译成功。✅
