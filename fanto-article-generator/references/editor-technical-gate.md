# 编辑技术预审清单（Editor Technical Gate）· 必查门禁

> **定位**：**必查门禁（强制）**。进 SKILL.md 阶段四B 交付总闸门的聚合判定——①④⑤⑥ 为裁决级（可归因放行），**②指代逻辑 / ③技术机制精确 任一 🔴 = 阻塞**，未修不得交付。
> **与 C2/C3/C3.6 的本质区别**：那三道是"**改好**"（润色向），这套是"**核查**"（是否说得对/准/自洽/可渲染）。
> C2 抓语法语感、C1.6 抓事实保真、C3.6 抓风格锐度；本清单抓 **语义、技术事实、指代逻辑、概念一致性、渲染等价性、品牌大小写** —— 这是四人格润色与 C3.6 覆盖不到、机械扫描又查不出的层（作者自检与审校者共享同一大脑盲区）。
>
> **使用方式**：写完逐段核查（技术机制句、跨段角色词、品牌大小写优先），**必须**在阶段四B 输出核查表并给出 ②③ 有无 🔴 的裁决。

## 为什么需要这道检查

2026-08-28 的 SDLC 转述文章在 4 轮审校中才收敛，败因集中在以下几处，全部逃过了现有防线：

- 温和口语词（跑顺了/摊开讲/兜底/练熟/活儿/跟单/动手）——标题位只查 L3，正文全逃逸。
- 指代不明（"根据它先 mock 出设计"，"它"指 Claude Design 还是 intent.md？）。
- 逻辑瑕疵（"从流水线变回循环"——传统流程从不是循环，应是"重构为"）。
- 技术机制不精确（Plan Mode 说成"不能改文件"，实为"只读状态、无写入权限"）。
- 渲染不兼容（`$1\sigma$` LaTeX，公众号/微信不渲染，会显示裸 `$..$`）。
- 中文自造概念不一致（"想点子的人" vs 执行步骤的"提出者"；"Claude Design（beta）" vs "Claude Tag（公测）"一英一中）。
- 品牌大小写混用（正文 `AI-native` 小写 vs 书名 `AI-Native` 大写）。

把这 7 处反例固化成下面的 6 类核查项，逐类打勾。

## 六类缺口（逐类过一遍，每类都要有明确裁决）

### ① 正文口语词（温和口语，非标题位）

**核查**：全文（含列表项，超出 C2 扫描 10 的标题位范围）是否残留"温和口语词"——这些词在**工程博客/技术复盘/商业分析**体裁（阶段 1.2 词汇约束：禁止口语动词）属必改，但在模式 A / 掘金 / 公众号允许一定口语度。

**方法**：对每个命中的词问一句："这个词在技术分享会上会被人说出口吗？"
- 会 → 保留（模式 A/掘金 OK）。
- 不会 → 改写为书面语。反例：`跑顺了`→`落地`、`摊开讲`→`讲清楚`、`兜底`→`作为最终防线`、`练熟`→`演练到位`、`活儿`→`工作/子任务`、`跟单`→`逐项跟进`、`动手`→`生成修复方案并提交 intent.md`、`闷头`→`一次性`。

> C2 扫描 12 已机械列出候选；本项只做"保留/改写"裁决，不重复搜索。

### ② 指代与逻辑自洽

**核查**：每个代词/指示词（它/这/那/这些/这种）是否回指**唯一**；每个"变 A 为 B / 变回 / 变成 / 重新"表达是否符合起点逻辑；每个因果方向是否正确。

**三问法**（逐句过）：
1. 这句的"它/这/那"指谁？找一个读者能唯一确定的先行词——找不到就是指代不明。
2. 这句"变 A 为 B"——A 真的是原来的吗？B 真的是新增的吗？"变回"意味着从前就是 B，若非 → 改"重构为/变为/改成"。
3. 这句描述的动作/机制，是原文真的这么做，还是我顺手上写的？

反例：`根据它先 mock 出设计`（"它"歧义）→ `在 Claude Design 中载入该文档生成 UI 原型`；`变回循环`→`重构为自循环`。

### ③ 技术机制精确性

**核查**：每一处描述**产品/工具行为、架构机制、数据流**的句子，是否精确到"它到底是什么、在什么条件下做什么"。这是审校中最容易被发现、也最伤可信度的一类——润色人格（工程师）只关注 benchmark 标注与架构自洽，不专门核对"这个机制描述是否与产品真实行为一致"。

**方法**：对每个机制句，尝试用一句话复现"对象 + 前置条件 + 动作"。能复现且与产品知识/英文原文一致 → 过；复现不出或用词含糊 → 回原文/文档核实。

反例：Plan Mode 说成"Claude 在计划通过前不能改文件"→ 精确为"只读推演状态、无法对代码文件执行写入操作"。

> 涉及英文原文的技术机制句，可复用 C1.6 回译路径：把中文机制句回译成英文对照原文，比对措辞是否等价。

### ④ 渲染等价性（目标发布环境）

**核查**：全文是否出现目标渲染器（公众号/微信 / Markdown CMS）**不支持或会错误显示**的语法。这类错误用户预览时才暴露，返工代价高。

**高风险语法清单**：
| 语法 | 风险 | 处理 |
|---|---|---|
| LaTeX `$..$`、`$$..$$` | 公众号/微信不渲染，显示裸 `$1\sigma$` | 改成直接字符 `1σ`（希腊字符）或中文 |
| LaTeX 命令 `\sigma` 等 | 残留原样输出 | 删除，换成字符 |
| 裸 HTML 标签 `<br/>` `<div>` 等 | 编辑器可能吞掉或报错 | 改用 Markdown 或转义为代码 |
| MathML / `<math>` | 大多数平台不渲染 | 用文字/字符 |

> C2 扫描 13 已机械标记；本项裁决是否替换。

### ⑤ 中文自造概念 / 角色 / 状态词一致性

**核查**：全文盘点**你自造的中文角色词、状态词、概念名**——同一个概念是否始终用同一个词，且英文专名首现是否 bilingual 加注。G19 只管"英文术语译法闭环"，**管不了中文自造词**，因此漏网。

**方法**：
- 角色词：同一"人"在文中出现 ≥2 次，是否用了同一称呼？（首现可全称、后续简称，但要一条术语链）反例：`想点子的人` vs `提出者` → 统一为`需求提出者`（首现）→`提出者`（简称）。
- 状态词：同一产品状态（beta/公测）是否始终同一写法？反例：`Claude Design（beta）` 与 `Claude Tag（公测）` 一英一中 → 统一（中文专栏统一用"公测"）。
- 概念名：自造概念首现是否 `中文（English）` 双语加注？反例：`提交产物（committed artifact）` 是正确作法；裸用 `agentic` 无加注则需补。

### ⑥ 品牌 / 标题大小写规约

**核查**：区分**书名/标题式**（实词首字母大写：`The AI-Native SDLC Playbook`）与**正文普通引用式**（修饰词小写：`AI-native`）。同类语境（都当书名 / 都当普通词）禁止混用。

**判定**：
- 两种拼写分别出现在"书名/标题"和"正文"两种语境 → **可保留**（属英文排版惯例）。
- 同一语境（都当书名，或都当正文）出现不同拼写 → 统一。

> C2 扫描 15 已机械列出并存；本项做"是合法双轨还是同语境混用"的裁决。

## 输出格式（进入阶段四B 门禁判定时用）

```
=== 编辑技术预审（目标媒体：[X] / 体裁：[Y]）===
① 正文口语词：C2 标记 [N] 处 → 保留 [M] 处（模式A/掘金可）/ 改写 [N-M] 处：[逐一列改写]
② 指代与逻辑自洽：[N] 处 → [句 → 问题 → 修正]
③ 技术机制精确性：[N] 处 → [机制句 → 原文/文档核实 → 精确化]
④ 渲染等价性：LaTeX/裸HTML [N] 处 → [替换为]（无则填 0）
⑤ 概念/角色/状态一致性：[N] 处 → [统一为]
⑥ 品牌/标题大小写：[N] 处 → [标题式 vs 正文式 裁决：保留/统一]

```

**门禁判定**：②③ 任一 🔴（指代不明 / 机制不精确）= **阻塞**，须修正后重跑，未修正不得进交付；①④⑤ 的裁决尽量可归因（记下"为何保留"）。

## 与既有步骤的关系

- **与 C2 扫描 12-15**：C2 做"机械标记"，本清单做"人脑裁决"。C2 报的提示（正文口语词 / LaTeX / 半角标点 / 品牌大小写）都在此裁决；反过来本清单能发现 C2 报不出的（②指代 / ③技术机制）。
- **与 C1.6 回译**：C1.6 保"事实不漂移"，本清单管"事实表述是否精确自洽"。技术机制句可复用回译核对原文。
- **与 C3.6 锐化**：C3.6 在前（改好风格），C3.7 在后（核查内容）——顺序不能颠倒，否则锐化会冲淡核查对象。
