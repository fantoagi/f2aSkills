## 二、8 大改写手法标注

按"出现位置 + 改写手法 + 为什么这样改"三列对照。

### 手法 1：顶部 clippings-style 来源标注（公众号合规必填）

**位置**：frontmatter 后、文章标题前

**原版（v1/v2）**：
```markdown
> 本文转译自 Khairallah AL-Awady @eng_khairallah1 2026-06-08 发布的 X 长文。按模式 C 忠实翻译子模式处理：保留原文 5 分类与 30 个 prompt 名称的 1:1 对应...
```

**改写后（v3）**：
```markdown
> **来源**：[@eng_khairallah1](https://x.com/eng_khairallah1) | **发布**：2026-06-07 | **标签**：clippings
```

**为什么这样改**：
1. **公众号合规**：标注"clippings"标签 = 主动声明"我是转载"。避免被原作者投诉原创归属
2. **视觉简洁**：单行 3 字段（来源/发布/标签）比 v2 的多行 blockquote 更适合公众号信息密度
3. **可点击**：`@eng_khairallah1` 是 markdown 链接，公众号渲染时直接可跳转到作者 X 主页
4. **日期差异**：原文发布是 2026-06-07（原文作者发文日），不是 2026-06-08（CDP 抓取日）。v3 用了原文发布日；v2 用了抓取日。**真实发布日**对原作者致谢更准确

### 手法 2：标题"开箱即用 / 秒变" 公众号爆款词

**位置**：frontmatter title + H1

**原版**："Khairallah AL-Awady 的 30 个 system prompt 速查手册：写作、调研、商业、编程、效率"

**改写后**："30 个开箱即用的 System Prompt，让 Claude 秒变任何领域的专家"

**为什么这样改**：
1. **人称转换**："Khairallah AL-Awady 的 30 个..." → 去掉人物前缀（公众号读者不关心译者认不认识原作者）
2. **爆款词替换**："速查手册" → "开箱即用 + 秒变"。前者是工程师调性，后者是公众号爆款调性
3. **长度优化**：28 字 → 22 字。公众号标题 22 字左右最舒服（移动端标题区显示完整）
4. **"Claude 秒变任何领域的专家"** — 是公众号经典 CTA 句式（"X 秒变 Y"），匹配读者对"开箱即用"的预期

### 手法 3：emoji section 锚（视觉断点）

**位置**：5 大类标题前

**原版**：
```markdown
## 写作与内容（Prompts 1-8）
## 调研与分析（Prompts 9-14）
## 商业与战略（Prompts 15-20）
## 编程与技术（Prompts 21-26）
## 个人生产力（Prompts 27-30）
```

**改写后**：
```markdown
## 📝 内容与写作（提示词 1-8）
## 🔍 研究与分析（提示词 9-14）
## 💼 商业与战略（提示词 15-20）
## 💻 编码与技术（提示词 21-26）
## ⚡ 个人生产力（提示词 27-30）
## 🛠 如何使用这些提示词
```

**为什么这样改**：
1. **公众号长文视觉节奏**：6 个二级标题用 emoji 区分，读者扫读时一眼能定位章节
2. **跨平台兼容**：微信公众号 / 知乎 / 头条都支持 emoji 渲染
3. **emoji 选择**：
   - 📝 写作（笔 + 本）
   - 🔍 研究（放大镜，调查/分析）
   - 💼 商业（公文包）
   - 💻 编程（电脑）
   - ⚡ 生产力（闪电）
   - 🛠 工具使用（扳手）
4. **避免"中性 emoji"**：不选 🟦/🔵/⭕ 等纯装饰性 emoji。每个 emoji 必须有语义

### 手法 4：Bilingual prompt 名（中文 + 英文括号）

**位置**：每个 prompt 标题

**原版**：
```markdown
### 01. The Viral Article Writer — 病毒式爆款写手
```

**改写后**：
```markdown
**01. 爆款文章写手 (The Viral Article Writer)**
```

**为什么这样改**：
1. **B 加粗而非 H3**：v2 用 ### H3 走 markdown 标准结构；v3 用 **bold** 让 prompt 列表在公众号渲染时**视觉更像"目录"**而非"章节"
2. **中文在前**："爆款文章写手"放前面，公众号读者扫读时中文第一眼命中
3. **英文括号在尾**：`(The Viral Article Writer)` 让做英文搜索的工程师能反查
4. **去掉破折号**："—" 改成 "()"。公众号渲染括号比破折号干净

### 手法 5：短句 + 情感 emoji

**位置**：开头 hook、结尾 CTA

**原版**：
```markdown
秘密就在 system prompt 里。大多数人对 system prompt 的态度是：要么完全跳过，要么写一行没用的废话。
```

**改写后**：
```markdown
区分"拿到泛泛 AI 输出"和"每次都能拿到专家级结果"的，只有一件事。  
先收藏这篇 :)  
不是什么秘密技巧，不是付费课程，也不需要多年经验。  
是 **System Prompt（系统提示词）**。
```

**为什么这样改**：
1. **反差句开头**："区分 X 和 Y 的，只有一件事" — 公众号 10w+ 爆款公式
2. **"先收藏这篇 :)"** — 微信公众号特有的"求收藏" CTA + 情感 emoji。比 v2 的中性"Save this :)"翻译更地道
3. **逐行短句**：3 行独立成段，公众号移动端阅读节奏感更强

### 手法 6：受众扩写（隐性加注）

**位置**：Prompt 01 第一段

**原版**：
```markdown
你是一位专注 AI 与科技领域的爆款内容创作者。读者是 X 上 20 万+ 规模的 AI 工具初学者群体。规则：
```

**改写后**：
```markdown
你是一位专注 AI 与科技领域的爆款内容创作者。目标受众是 X 平台上 20 万+ 规模的初学者群体，他们大多是初次接触 AI 工具的新手。  
规则：
```

**为什么这样改**：
1. **"X 上 20 万+ 粉丝"** vs **"X 平台上 20 万+ 规模的初学者群体"** — 后者消歧义（v2 的"20 万+ 粉丝"读者会误解为"作者有 20 万粉丝"）
2. **"他们大多是初次接触 AI 工具的新手"** — **这是原文没有的补充**。属于公众号改编的"扩写"层（v3 在透明披露这一点——见末尾批注）
3. **隐性风险**：扩写改变了原意。**公众号改编子模式允许这种扩写**，忠实翻译子模式**禁止**。模式分流时务必确认

### 手法 7：行业术语本地化（"他们" / "过来人" 语态）

**位置**：每个 Prompt 的开场

**原版**：
```markdown
你把长文转成 X/Twitter 帖文。规则：
```

**改写后**：
```markdown
你将长篇文章转换为 X/Twitter 推文串。  
规则：
```

**为什么这样改**：
1. **"X/Twitter 帖文"** → **"X/Twitter 推文串"**。"推文串"是 X 中文官方译法（类比"原推/转推"）
2. **"转" → "转换"**：单字"转"在中文里偏口语，公众号语境用"转换"更正式
3. **行业术语本地化**：在 `cross-cultural-terms.md` 表里查"Thread" → "推文串"，避免"线"（Thread 字面）"线 列"等奇怪直译

### 手法 8：情感 emoji 收尾（CTA 软化）

**位置**：全文最后一行

**原版**：
```markdown
希望对你有用。

— Khairallah
```

**改写后**：
```markdown
希望这对你有帮助，Khairallah ❤️
```

**为什么这样改**：
1. **❤️ 软化语气**：从"宣告结语"变成"创作者与读者的温暖告别"
2. **去掉"—" 署名破折号**：v2 用 "— Khairallah" 是英文信末署名格式。v3 直接逗号 + 名更亲切
3. **公众号情感互动**：❤️ 鼓励读者点赞/在看/转发

## 三、与忠实翻译的差异清单

| 维度 | 忠实翻译 (C-faithful) | 公众号改编 (C-publication-adapted) |
|------|---------------------|----------------------------------|
| 标题 | 30 个 system prompt 速查手册 | 30 个开箱即用的 System Prompt，让 Claude 秒变任何领域的专家 |
| 来源标注 | 文末 2 行斜体 | 顶部 clippings-style + 末尾 2 行斜体（双标） |
| 章节标题 | H2 ## | H2 ## + emoji 锚 |
| prompt 标题 | H3 ### | bold **（不再用 H3） |
| Prompt 名 | 中文单一 | **Bilingual**（中文 + 英文括号）|
| 受众描述 | 严格按原文"X 20万+ followers" | **扩写**"他们大多是初次接触 AI 工具的新手"（隐性加注）|
| 行业术语 | 多数保留英文 | **本地化**（"推文串" / "路人缘" 等）|
| 开头 hook | "秘密就在 system prompt 里" | "区分 X 和 Y 的，只有一件事"（反差句）|
| 收尾 | 干干的中性 CTA | 情感 emoji 软化 |
| 调性 | 工程师/记者克制 | 公众号爆款 + 适度 SEO |
| 排版 | 段落长、列表密 | 段落短、视觉断点多 |
| 加注格式 | 行业缩写首次 `(TLA)` | 同左 + 跨文化术语首次本地化注释 |

## 四、v3 仍有的可改进点（不完美，承认）

1. **Prompt 12 与 Prompt 17 的"投资"措辞不一致**：
   - Prompt 12（市场规模估算器）末尾 "推荐定价点及定位依据" 没说投资
   - Prompt 17（客户提案写手）说"以'投资'而非'成本'呈现"
   - **统一方案**：让 Prompt 12 末尾加一行 "提示：与 Prompt 17 联动，定价当投资讲"

2. **Prompt 01 受众扩写**（"他们大多是..."）没有标注为扩写：
   - 公众号改编允许扩写但应透明
   - **改进方案**：在文末加一段 "本文在以下地方做了[微调/扩写]，供你参照" 的批注栏

3. **emoji 使用密度**：每节 1 个 emoji 共 6 个。公众号长文传统 2000-3000 字建议 8-12 个 emoji。v3 的 6 个偏少。**改进方案**：每个 H2 标题加 1 个 emoji，每个 H3 标题不加（避免 emoji 噪声）

4. **CTA 单一**：v3 的 CTA 只有"挑 5 个搭 Project"一处。公众号长文传统会在文中 + 结尾各放 1 个 CTA。**改进方案**：开头 hook 后加一句"文末有具体怎么用"

## 五、何时复用本示例

**完全复用**：
- 下次翻译 X 长文到公众号，且源材料是 5 分类 + 多 prompt 列表
- 下次写关于 AI 工具 / 创业方法论 / 行业 best practice 的公众号长文
- 下次用户给 30 / 50 / 100 个 X 长文 → 公众号场景的批量翻译

**部分复用**：
- 文章是 5 分类以外的结构（时间线 / 案例分析 / 评测对比）— 复用手法 1、2、4、5、6、8
- 文章是英文 推文 thread 而非长文 — 复用手法 1、4、6
- 文章是播客稿 / 视频字幕 — 复用手法 1、5、7、8 + 改手法 3（去掉 emoji 标）

**不适用**：
- 文章是 学术论文 / 专利 / 财报 — 用忠实翻译子模式，不用本示例
- 文章是 个人学习笔记 / 内部周报 — 用改写转述子模式，不公开调性
- 文章是 英文 SEO 博客 — 用英文原文模式（保留所有英文）

## 六、给 main agent 的执行清单

下次接模式 C 公众号改编任务时，按这个顺序跑：

1. ☐ 读 `references/cross-cultural-terms.md`（改动 2 落地）
2. ☐ 读 `references/editor-polish-checklist.md`（改动 3 落地）
3. ☐ 读本文件 `mode-c-publication-example.md`（改动 4 落地）
4. ☐ 提取源材料（X / 播客 / 视频）— 完整 1:1 翻译
5. ☐ 跑 8 大改写手法（顶部 clippings / 标题爆款 / emoji 锚 / bilingual 名 / 短句 / 受众扩写 / 术语本地化 / 情感 emoji）
6. ☐ 跑 1:1 名称对账（SKILL.md 修复 4 闸门）
7. ☐ 跑 C2 + 3 组 grep（公众号改编子模式必填）
8. ☐ 跑资深编辑 polish 清单（12 类软错）
9. ☐ 写 frontmatter（mode: C-publication-adapted, date: 当前日期）
10. ☐ 末尾出处标注（双标：顶部 + 末尾）
11. ☐ 渲染预览 + preflight + 等用户确认 + publish

**平均耗时**：4500-5500 英文词 → 1.5-2 小时 main agent 劳动（vs 忠实翻译 30-40 分钟）。多花的 60% 时间换公众号可发性 + 资深编辑级质量。

## 历史教训

- 2026-06-09 v1 → v2 → v3 三个回合迭代：v1 (忠实翻译, 18/30 错位) → v2 (忠实重译, 30/30 对齐) → v3 (公众号改编, 8 大手法全用上)。三步顺序不可跳——没有 v2 的 1:1 对账，v3 的 bilingual 名可能错位；没有 v1 的失败，v3 的 8 大手法可能是空中楼阁
