# 目标媒体语感配置 (Media Voice Profiles)

> **定位**：翻译/改写阶段前加载，按目标发表渠道调整语感参数。不做翻译规则，只做"同一篇译文在不同媒体的发音方式"。
> **加载时机**：SKILL.md 阶段一（模式判定）之后，阶段二（翻译）之前。用户未指定媒体时默认 `wechat`。
> **与 mode-c.md 的关系**：mode-c.md 定义"怎么写"，本文件定义"写给谁看"。

## §1 WeChat 公众号（默认）

**读者画像**：泛 AI 从业者、产品经理、创业者、技术爱好者。碎片时间滑动阅读。

### 语感参数

| 参数 | 设定 |
|------|------|
| 句长偏好 | 15-35 字为主，偶有 50 字长句制造节奏变化 |
| 段落长度 | 2-4 句，移动端不压迫 |
| 技术深度 | 概念级——讲清"是什么/为什么重要"，不讲实现细节 |
| 引语密度 | 高——每章 2-4 处直接引语，用 `>` 引用块制造停顿 |
| 判断句式 | 中等——有立场但不咄咄逼人 |
| 动词力度 | L2 专业口语——"跑分很强"而非"表现优异"亦非"牛逼炸了" |
| 章节数 | 5-8 节 |
| 单节字数 | 200-500 字 |

### 开篇策略

优先级：**场景共鸣 > 数据冲击 > 概念悬念**

```
[一句话锚定读者熟悉的场景/困惑] → [引出今天要讲的核心问题] → [过渡到正文]
```

### 标志性结尾

`> [一句可独立传播的金句]` + 来源标注行

## §2 极客公园 (GeekPark)

**读者画像**：关注产品与行业趋势的科技从业者、产品经理、创始人。比公众号读者更硬核，比 36Kr 读者更偏产品思维。

### 语感参数

| 参数 | 设定 |
|------|------|
| 句长偏好 | 15-40 字，允许偶有 60 字复杂判断句 |
| 段落长度 | 2-5 句 |
| 技术深度 | 机制级——允许讲"怎么做到的"，但不过度展开实现细节 |
| 引语密度 | 中高——保留关键引语，但分析性过渡句占比增加 |
| 判断句式 | 偏高——每节至少 1 句有立场的判断。**判断必须具体**：不说"这一变化意义重大"，说"这一变化意味着 X 不再需要 Y" |
| 动词力度 | 锐利克制——"刺破""解耦""重构""抢先"。不用"颠覆""革命"等过度词 |
| 章节数 | 6-9 节 |
| 单节字数 | 250-500 字 |

### 开篇策略

优先级：**反常识判断 > 产品冲突 > 数据对比**

```
[一句有态度的判断句] → [具体证据/场景] → ["这意味着……"过渡]
```

示例：
> 好的：`Anthropic 做了一件反直觉的事：他们主动给增长踩了刹车。不是融不到钱，是算力不够用。`
> 差的：`Anthropic 最近发布了一系列更新，引发了行业关注。`

### 动词力度梯度（针对 GeekPark 校准）

对照同一语义，按力度从弱到强选词。默认选中档（L2），核心论断句可选高档（L3）：

| 语义场 | L1 弱/模糊 | **L2 标准** | **L3 锐利**（核心论断专用） |
|--------|-----------|------------|--------------------------|
| 消除/去掉 | 去除/移除 | 砍掉/剔除 | **斩断**（仅用于结构性依赖） |
| 揭露/暴露 | 揭示/显示 | 暴露/刺破 | **戳穿**（仅用于行业幻觉/叙事泡沫） |
| 创造/建立 | 创建/搭建 | 构建/拉起 | **锻造**（仅用于长期系统工程） |
| 超越/领先 | 超越/领先于 | 甩开/拉开 | **绝尘**（慎用，仅用于明确代差） |
| 改变/转型 | 改变/转变 | 重塑/重构 | **翻篇**（仅用于范式级变化） |
| 加速/加快 | 加速/推进 | **踩下油门**（口语化但有力）| — |

**L3 使用限制**：全文最多 3 处，且仅在核心论断句使用。滥用 L3 会稀释力度。

### 标志性结尾

不靠金句收束，靠判断收束：

```
[回扣开篇的核心张力] → [给出一个可证伪的预测或观察] → 来源标注
```

## §3 36氪 (36Kr)

**读者画像**：投资人、创业者、企业中高层。关注商业逻辑、竞争格局、资本流向。

### 语感参数

| 参数 | 设定 |
|------|------|
| 句长偏好 | 20-45 字，逻辑严密优先于朗朗上口 |
| 段落长度 | 3-5 句 |
| 技术深度 | 商业级——技术细节只在解释商业逻辑时才展开 |
| 引语密度 | 中低——直接引语服务于论点，不服务于叙事节奏 |
| 判断句式 | 高——核心是"这意味着什么"和"为什么现在发生" |
| 动词力度 | 专业分析——"押注""卡位""出清""出牌"。多用商业分析动词，少用技术操作动词 |
| 章节数 | 5-7 节 |
| 单节字数 | 300-600 字 |

### 开篇策略

优先级：**市场信号 > 竞争格局变化 > 数据冲击**

```
[一个具体的市场信号或竞争动作] → [为什么这个时间点值得关注] → ["这背后的逻辑是……"过渡]
```

示例：
> 好的：`6 月，Anthropic 的 API 收入跑了 80 倍增长。同一周，他们宣布对新用户限速。这是算力不够的信号，但更深一层——这是 AI 商业模式从"规模优先"转向"效率优先"的转折点。`
> 差的：`Anthropic 最近收入增长很快，但他们选择了限速。`

### VC/商业术语映射（补充 glossary-ai.md §4 未覆盖的）

| 英文 | 36Kr 标准表述 |
|------|-------------|
| `product-market fit` | 产品市场验证 / 跑通 PMF |
| `go-to-market` | 商业化落地 / 推向市场 |
| `land grab` | 抢地盘 / 圈地（战略语境） |
| `incumbent` | 既有厂商 / 在位巨头 |
| `disruptor` | 破局者 / 新锐 |
| `margin profile` | 毛利结构 / 单位经济模型 |
| `cohort retention` | 同期群留存 / 用户粘性 |
| `capital efficiency` | 资本效率 / 钱烧出来的效率 |
| `defensible` | 有壁垒 / 护城河够深 |
| `total addressable market` | 市场天花板 / TAM |

### 标志性结尾

```
[回到商业逻辑主线] → [一个可被后续验证的判断] → ["值得持续关注"收束] → 来源标注
```

## §4 掘金 (Juejin)

**读者画像**：一线开发者、工程师、技术 Leader。读代码比读文字多。对"感觉"和"趋势"不买账，只认可复现的逻辑和可运行的代码。

### 语感参数

| 参数 | 设定 |
|------|------|
| 句长偏好 | 10-30 字，短句为主。代码块占比显著高于其他媒体 |
| 段落长度 | 1-3 句。代码块前后短段过渡 |
| 技术深度 | 实现级——允许展开架构、API 设计、数据流、tradeoff 分析 |
| 引语密度 | 低——用代码块和架构描述代替直接引语 |
| 判断句式 | 低——"方案 A 比方案 B 好在哪"优于"这个方向是对的" |
| 动词力度 | 工程操作——"跑通""写死""硬编码""兜底""拉起""挂掉" |
| 章节数 | 4-7 节（含代码块） |
| 单节字数 | 150-400 字（代码块不计入字数） |

### 开篇策略

优先级：**技术问题 > 工程痛点 > 工具对比**

```
[一个具体的工程问题或 tradeoff] → [传统解法及其局限] → ["本文的方案是……"过渡]
```

示例：
> 好的：`用 Claude Code 跑了三个月，最头疼的不是代码写不对，是上下文窗口撑爆后行为退化。每次到 85% 窗口占用，Agent 就开始"忘事"。本文给一个生产可用的压缩策略。`
> 差的：`Claude Code 是一个强大的 AI 编程工具，但在使用过程中会遇到一些问题。`

### 开发者语域映射

不装外行，也不装内行。用工程师日常交流的措辞：

| ❌ 外行/翻译腔 | ✅ 工程日常 |
|---------------|-----------|
| 执行一次调用 | 调一次 |
| 通过 API 接口获取 | 拉一下 API |
| 持续集成流水线 | CI pipeline |
| 上下文窗口已满 | 窗口爆了 / 上下文撑爆 |
| 模型返回了错误结果 | 模型输出有 bug |
| 进行本地化部署 | 本地跑 / 私有化部署 |
| 该问题已被修复 | 修了 / fixed |

### 代码块规范

- 每个代码块必须标注语言（掘金渲染依赖语言标签）
- 代码块前后各空一行
- 超过 30 行的代码块在开头用注释标注"这段在做什么"
- Shell 命令用 ` ```bash `，不要用 ` ```shell `

### 标志性结尾

```
[可复现的核心结论] → [GitHub/在线 demo 链接（如有）] → 来源标注
```

## §5 知乎 (Zhihu)

**读者画像**：泛知识人群，期待深度和"长答案感"。愿意读长文，但要求信息密度配得上阅读时间。

### 语感参数

| 参数 | 设定 |
|------|------|
| 句长偏好 | 15-40 字，允许复杂逻辑句 |
| 段落长度 | 2-6 句 |
| 技术深度 | 概念到机制均可，取决于话题 |
| 引语密度 | 中——引用服务于论证，不是叙事 |
| 判断句式 | 中高——"我的判断是……"优于"这意味着……" |
| 动词力度 | 专业但不锐利——"推演""论证""拆解""辨析" |
| 章节数 | 6-10 节 |
| 单节字数 | 300-600 字 |

### 开篇策略

优先级：**问题意识 > 认知冲突 > 热点切入**

```
[一个值得回答的问题] → [现有答案的不足] → ["本文尝试从 X 角度拆解……"]
```

## 媒体切换执行 SOP

在 SKILL.md 阶段一判定模式后、阶段二翻译前，增加一步：

### [强制输出—阶段 1.3：媒体语感判定]

```
目标媒体：[WeChat / GeekPark / 36Kr / Juejin / Zhihu]
触发关键词（用户原话）：["…"]
已加载语感配置：references/media-voice-profiles.md §[1-5]
语感参数摘要：[句长 / 技术深度 / 动词力度 / 开篇策略]
```

未指定 → 默认 WeChat。用户原话含多个媒体关键词 → 按第一个明确命中的为准。

### 语感校准注入（翻译前）

在阶段二翻译开始前，从 `references/media-voice-profiles.md` 对应章节提取以下参数，注入翻译 prompt 头部（与确定性基座并列）：

```
🎯 目标媒体：[名称]
- 句长偏好：[X-Y 字]
- 动词力度：[L2/L3 + 示例]
- 开篇策略：[优先级]
- 技术深度：[级别]
- 禁用词：[该媒体特有的禁用表述]
```
