# 模式 B：行业快讯 — 完整规范

> 由 `SKILL.md` 按需加载。英文源材料先查阅 `references/ai-translation-guide.md` 做精准翻译后再按本模式改写。

## 🎯 核心写作调性（必须严格遵守）

行业快讯模式必须采用更接近科技媒体快讯稿的表达方式：

1. **专业、克制、信息密度高**：句子要干净，信息要集中，不写聊天体，不写情绪化铺垫。
2. **直接进入事实与判断**：开头直接交代"发布了什么、升级了什么、为什么值得关注"，不要从抓狂场景或人物代入切入。
3. **像媒体快讯，不像专栏杂谈**：核心是快速传递重点，而不是做概念启蒙。
4. **以事实句和判断句为主**：多写"发布了什么、达到了什么、支持什么、意味着什么"，少写松散的解释性过渡。
5. **默认中文输出**：即使参考材料为英文，最终正文也默认输出中文行业稿。

## 📜 行业快讯写作 SOP

1. **先抓新闻核心**：明确本次发布、更新或行业变化最值得关注的 2-4 个点。
2. **先定信息优先级**：优先回答：
   - 发布了什么
   - 核心能力或变化是什么
   - 处在什么行业位置
   - 用户或开发者如何使用 / 接入
3. **按快讯结构撰写**：
   - **标题**：科技媒体快讯标题，直接、清晰、有信息量
   - **开头**：一句话交代发布事实与关键信号
   - **第一部分**：核心升级点
   - **第二部分**：行业定位 / 对标关系
   - **第三部分**：接入与使用方式
   - **结尾**：一句凝练判断或总结
4. **控制篇幅**：优先压缩冗余解释，保证读者能快速扫完重点。
5. **生成本地文件**：使用 `Write` 工具，在用户当前工作目录下创建 Markdown 文件。

## 🧭 行业快讯标题规则

- 不使用 `番外篇 XX｜` 这类专栏标题格式。
- 标题要像科技媒体快讯：
  - 直接写主体 + 事件 + 关键信息
  - 示例：`DeepSeek-V4 发布并开源：Agent、推理与 1M 上下文同步升级`
  - 示例：`OpenAI 发布新模型：多模态能力首次进入实时语音产品`
- 标题可以有张力，但不能浮夸，更不能像营销号。

## 🚫 行业快讯禁忌

- 不要写成大白话解释文。
- 不要使用强比喻作为主结构。
- 不要使用"你一定遇到过""很多老板第一次听到"这类口语开头。
- 不要写成"本文将介绍"的教科书腔。
- 不要写成产品宣传稿。
- 不要使用模糊、发虚的词，比如"区间""一档""口径""比较的区间"这类表达，除非是在转述原句且无法替换。
- 不要出现拖沓的过渡句，比如"这一部分其实可以很快看完""也就是说大家都知道"。

## ✅ 行业快讯自检

写完后必须检查：

1. 开头是否直接进入发布事实，而不是场景铺垫。
2. 是否优先写清"升级点 / 对标位置 / 使用方式"。
3. 是否保持正式、克制，而非聊天体或宣传腔。
4. 是否删掉了含混、发虚、绕弯的表达。
5. 即使参考资料是英文，正文是否仍然默认输出为中文。
6. 整体是否更像科技媒体快讯，而不是专栏解释文。
