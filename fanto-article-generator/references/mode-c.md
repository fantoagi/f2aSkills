# 模式 C：AI 一线对话转述 — 完整规范

> 由 `SKILL.md` 按需加载。
>
> **英文源材料强制流程**：英文播客/访谈/转录 → 先查阅 `references/ai-translation-guide.md` 按 3 阶段流程做精准翻译 → 再按本模式改写为转述文章 → 完成后对照翻译指南自检清单逐条检查。禁止跳过翻译步骤直接"提炼事实+重写"。

## 🎯 核心写作调性（必须严格遵守）

对话转述模式的目标是把一场重要的 AI 一线对话，用"科技记者整理稿"的质感呈现给中文读者：

1. **记者转述感**：像科技记者在整理一场重要对话——有信息量，有温度，但不是专栏杂谈。你的角色是"转述者"，不是"评论员"也不是"翻译机器"。
2. **大量直接引语**：保留 speaker 的原话质感，让读者"听到"他们在说什么。`"80 倍太疯狂了，是真的扛不住"` 比 `"Dario 表示增速难以承受"` 有力十倍。直接引语优先用粗体强调关键句。
3. **场景化叙事**：每章从对话中的自然转折切入，而不是 `"关于 X 问题，Y 认为……"`。好的引入是 `"Ami 追问：这些趋势会不会反过来改变 Anthropic 训练模型的方式？"`，差的引入是 `"接下来讨论模型训练问题。"`
4. **中文口语化但正式**：不要翻译腔，也不要把烧烤摊大白话带进来。目标语感是"一个表达很好的科技记者在跟你讲他刚听到的一场对话"——自然、清楚、有信息量，但不随意。
5. **章节独立可跳读**：每章读完后读者都有收获，标题本身就有信息量，支持公众号场景的快速浏览和选择性阅读。
6. **张力驱动叙事**：全文应围绕一个核心矛盾或主线展开——80 倍增长 vs 主动限速、印刷机解放 vs 护城河崩塌。每篇文章在动笔前先想清楚"这一篇的核心张力是什么"。

## 📐 文章固定骨架

### 标题公式

```
核心人物身份 + 冒号 + 最抓眼球的 2-3 个关键词/金句
```

- Boris 篇：`Claude Code 之父 Boris Cherny：编程正在经历自己的"印刷机时刻"`
- Dario 篇：`Anthropic 兄妹档最新对话全文：80倍增长、Amdahl 瓶颈、Mythos 未发布先防御`

规律：冒号前锚定人物，冒号后用具体数据/概念/金句钩住读者。避免空洞的形容词。

### 导语三段式

```
[引用式概括] → [时间地点人物上下文] → [话题弧线 + 过渡句]
```

- **引用式概括**：一句 `>` 引用块，高度概括这场对话的核心主题。例如 `> 半小时对话，Dario 和 Daniela 密集输出了 Anthropic 在指数曲线上的体感、取舍和下一步判断。`
- **上下文段**：1-2 句交代时间、场合、人物及其身份。例如 `5 月 6 日，Anthropic 在旧金山办了第二届 Code with Claude 开发者大会。新任 CPO Ami Vora 跟 CEO Dario Amodei、总裁 Daniela Amodei 坐下来聊了半小时。`
- **话题弧线 + 过渡**：一句话勾勒对话从哪到哪，然后用 `"这场对话的信息密度极高。以下是完整整理。"` 或类似表达过渡到正文。

### 正文分章：8-10 节

每章格式统一：

```
## 数字序号、观点金句标题

[场景/问题引入] → [核心观点陈述：直接引语 + 解释] → [数据/细节展开]
```

标题用 `## 一、二、三……` 编号，后跟该章最核心的观点或金句。

### 结尾两段式

```
[总结升华段] → [来源标注行]
```

- **总结升华段**：回到全文的核心张力，用一两句话提炼深层含义。不重复前文，而是给读者一个"带走的认知"。
- **来源标注行**：斜体，硬性格式为 `*本文内容全部来源于 [来源名] [场合/日期] "[环节名/标题]"，[链接类型]：[URL]。*` 如有多个来源如实列出。

## 🧩 章节类型菜单

从已验证文章中提炼的 7 种章节角色，按需选用和排序：

| 角色 | 功能 | 选用规则 |
|------|------|---------|
| **人物色彩章** | 建立人物形象，让读者"认识"这个人——有趣的习惯、比喻、反差 | 推荐放在第 1-2 节 |
| **核心数据章** | 最炸裂的数字或事实，制造冲击和记忆点 | 必选，尽早出现 |
| **概念定义章** | 解释一个贯穿全文的关键理念或框架 | 有则必选 |
| **宏大叙事章** | 历史类比或理论框架包装，提升文章高度 | 有则选，与概念章可合一 |
| **深度展开章** ×2-3 | 逐层展开核心论点，每个论点独立成章 | 必选，是文章主体 |
| **展望预测章** | 收束到对未来的判断或期待 | 推荐放倒数第 1-2 节 |
| **收尾缓冲章** | 轻松/人文内容，让读者带着温度离开 | 有则选，放在最后一节 |

组合原则：
- 每篇至少包含：人物色彩章、核心数据章、深度展开章 ×2-3
- 人物色彩章和核心数据章可以前置互换，取决于哪个更有冲击力
- 宏大叙事章可以跟概念定义章合为同一节（如 Amdahl 定律同时承担两个角色）
- 收尾缓冲章不可强求——源材料有温暖的细节才用，不要编造
- **单人长文变体**：当源材料是单作者长文（非多人对话）时，章节结构可跳过人物色彩章，以核心论点和深度展开章为主体

## ⚠️ 硬性质控规则（最高优先级）

这三条规则高于所有写作技法，写完后必须逐条对照检查。

### 规则一：来源保真——所有内容均源自原始素材，不得扩充、联想

这是底线规则。文章只做"转述、整理、翻译"，不做"扩展、补充、联想"。

- ✅ 可以：从源材料中提取观点，用中文重新表达，保留原话引用
- ✅ 可以：对源材料中分散的相关内容进行归类整理
- ❌ 禁止：添加源材料中未提及的背景知识、历史掌故、行业新闻
- ❌ 禁止：把 speaker 的观点引申到其他领域或与别的事件做连接
- ❌ 禁止：加入自己的分析、评价、或"这意味着……"式的推论
- ❌ 禁止：为丰富内容而从其他渠道补充信息

**检查方法**：文章中的每一句话，都能在源材料中找到对应。找不到的，删掉。

### 规则二：中文表达检查——对照翻译指南逐条检查

翻译完成后对照 `references/ai-translation-guide.md` 的自查清单检查：

- **翻译腔排查**：英文被动语态直译（"被允许"→"可以"）、长定语堆叠、代词指代不明、`when` 引导的状语从句直译
- **转录清理**：口语填充词（um, you know, like）、重复、口误、不完整句——转录可忠实保留，但文章应整理通顺
- **中文常见坑**：
  - "在这个层面上" → 删，"层面"是 level 的幽灵
  - "作为一个 X 来说" → "作为一个 X"或直接省略
  - "这是非常有趣的" → 除非真的有趣，否则删
  - "降了 X 倍" → 中文"倍"只用于增，降用"降到原来的 X 分之一"
  - "关于……的问题" → 删"的问题"
  - "在……的过程中" → 删或改写
- **数字/专名/术语准确**：源材料中的数字、人名、产品名、公司名必须与原文一致，不凭记忆写

### 规则三：原文配图可保留，位置必须对齐原文上下文

- 原始博客/翻译中的配图、截图可以直接复用
- **配图位置必须与原文一致**：每张图在源材料中紧接哪段文字之后，转述文章中就放在对应的内容段落之后，不要凭感觉重新排布
- **获取配图时同步提取位置信息**：从网页源抓取图片时，不要只提取 URL，必须同时提取每张图前后的文字上下文（如前一个 `[data-block]` 的文本摘要），用于写文章时精确还原图文对应关系
- 结尾必须标注：原始出处名称 + 类型 + 链接
- 格式：`*本文内容全部来源于 [来源名] [场合/发布日期] "[环节名/标题]"，[链接类型]：[URL]。*`
- 如果有多个来源（如原始视频 + 中文翻译参考），如实列出

## 📜 对话转述写作 SOP

1. **通读源材料**：完整阅读原始材料（转录、翻译或博客），不做跳读。**X/Twitter 源材料硬门禁：必须先走 CDP 浏览器提取**——用 CDP `/new?url=` 打开推文后 `/eval` 提取文本和图片，纯文本方式（WebFetch/Jina）会导致图片静默丢失。此检查在通读前完成，未确认图片 URL 列表前不得进入第 2 步。
2. **提取核心信息**：标注最核心的 5-8 个观点、最有力的直接引语、最有冲击力的数据、最打动人的细节。**如有配图，同步提取每张图的 URL 及其在原文中的位置上下文**（图片前紧邻的文字段落摘要），作为写文章时图文排版的依据。**对 X/Twitter 来源额外检测**：检查配图是否为动态图——如果 DOM 中出现 `tweet_video_thumb` 或 `tweet_video` 标签，说明原图是动画 GIF，需下载 MP4 并转换为 GIF（见 SKILL.md 总原则中的 GIF 检测规则）。
3. **确定核心张力**：想清楚这篇文章围绕什么矛盾展开——是速度 vs 安全？解放 vs 颠覆？预测 vs 现实？
4. **选配章节类型**：从章节类型菜单中按需选取 8-10 个章节角色，排定顺序。
5. **撰写标题和导语**：标题要有信息量和传播力；导语三段式完整。
6. **逐章撰写**：每章从场景/问题引入，核心观点用直接引语呈现，加数据/细节展开。
7. **三条约法自检**：逐条对照硬性质控规则，确保来源保真、中文自然、来源标注完整。

## 🚫 对话转述禁忌

- 不要扩充源材料中没有的内容——这是第一条也是最重要的一条。
- 不要把翻译腔带进中文——对照翻译指南检查。
- 不要加自己的分析、评价、"这意味着"式推论——你是转述者，不是评论员。
- 不要用"本文将介绍……"这类教科书腔开头。
- 不要写成大白话解释文——那是模式 A 的活。
- 不要写成行业快讯——那是模式 B 的活。
- 不要把 speaker 的观点引申到源材料未涉及的领域。
- 不要遗漏结尾的来源标注行。

## ✅ 对话转述自检

写完后必须检查：

1. 每句话是否都能在源材料中找到对应？（来源保真）
2. 中文表达是否自然，有无翻译腔？（读出声来，对照翻译指南自查清单）
3. 直接引语是否保留了原话的质感，而不是被转述成间接引语？
4. 来源标注是否完整，包含出处名称、场合和链接？
5. 标题是否有具体的信息量（数据/概念/金句），而不是空洞的形容词堆砌？
6. 各章节是否相对独立、标题本身就有信息量，支持跳读？
7. **源材料含配图时，是否已全部下载到本地并插入文章对应位置？**（X/Twitter 源材料尤其容易遗漏——纯文本获取方式不会报错，但图片静默丢失。）
