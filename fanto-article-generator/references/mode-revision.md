# 模式 R：微调（Light Revision）

> **定位**：已有成稿下的单点/多点修改。**不重跑完整 SOP**。
> **触发场景**：用户对已交付稿件提出修订意见（"X 处改成 Y"、"第三段太啰嗦"等）。
> **目标**：保留成稿主体，只对指定位置做精准修改，最大化复用、最小化副作用。

---

## 适用与不适用

**适用**：
- 用户对成稿的某词、某句、某段提出修改
- 用户列出多处需要调整的清单
- 用户对排版、引号、标点提出统一规范要求

**不适用**（应回到完整 SOP 重新跑）：
- 用户要求"重写整篇"或"换个风格"
- 用户要求新增一整节内容
- 用户对核心观点提出质疑（涉及"不可改清单"中的事实断言）

---

## 工作流（5 步，5–15 分钟）

### 1. 定位

- 读成稿全文（Read 工具）
- 用户意见若是自然语言（"那个'恢复差距'改成'弥合差距'"）→ 用 Grep 定位具体行号
- 用户意见若是成段描述（"脚注区太啰嗦"）→ 通读相关章节，列出待改点

### 2. 影响评估（每处修改前必做）

判断修改是否触及"不可改清单"：

- ❌ **不可改**：原文事实断言、数字、专名译法、因果逻辑、注脚编号
- ⚠️ **慎改**：原文语气强弱、章节标题、判断句的修饰语
- ✅ **可改**：译文的语序、搭配、句式、用词润色、引号/标点统一

触及"不可改"时主动与用户确认——不要为了"完成修改"而妥协保真度。

### 3. 改写

- 用 Edit 工具按定位结果逐处修改
- 每处 Edit 的 `old_string` 必须**唯一**（如不唯一，扩大上下文到唯一）
- 多处同类修改（如"全文引号统一"）用脚本（Python/Bash sed）批量处理
- 改完不读回整篇，直接进第 4 步

### 4. C2 单遍扫描（硬阻断，不可跳）

- 对改动涉及的章节/全文跑 9 组翻译腔 grep + 4 组新增 grep（语义反转 / 动宾跨域 / 名词堆叠 / 半角单引号）
- 触发 N>0 → 立即改写直到 0
- 跑 1 次即可，**不展开 5 subagent 物理隔离扫读**（快路径）
- **此步不可凭印象跳过**——即便主观认为改动无副作用。2026-06 实测中 5 处 Edit 后未跑本步，漏掉了 6 个半角单引号残留 + 漏检了"继承领先地位"在博弈语境的违和感。

#### 4.1 涉及批量标点/引号/格式修改时，必须额外跑偶数校验

**全角引号配对平衡扫描**（期望每行左右引号数差 ≤ 1，否则报错需人工复核）：

```bash
# 命中输出形如 "152: l=2 r=4"，表示 line 152 左 2 右 4，差 2 → 配对错位
awk '{ l=gsub(/“/,"&"); r=gsub(/”/,"&"); if (l-r>1 || r-l>1) print NR": l="l" r="r }' <译文>
```

**触发条件**（任一命中即必须跑本扫描）：
- 批量半角 `"` ↔ 全角 `"…"` 替换
- 批量单引号 `'` ↔ `'` 替换
- 批量顿号 ↔ 逗号
- 跨多行的标点统一

**硬底线**：本扫描不归零不可交付。2026-06 实测：line 152 因 1 个多余 `"` 导致 3 对引号方向反转（`”定方向”` 写成 `”定方向”`），肉眼未察觉，被用户二轮校对抓到。

**为什么需要这条**：半角 ↔ 全角引号批量替换的脚本若用"按行内出现顺序交替"算法，遇到奇数 `"` 的行会让从该行起所有配对全部错位，校验不过即拦截。

### 5. 朗读抽 1 段 + 交付

- 抽 1 段（**优先抽包含本次最大改动的段落**）做朗读，无卡顿 → 通过
- 输出交付报告（**精简版**，不要 16 项闸门）

---

## 交付报告模板（精简）

```markdown
## 修改清单
- <line X>：<原句> → <新句>（<一句话理由>）
- <line Y>：<原句> → <新句>（<一句话理由>）
- ...

## 闸门
- 不可改清单：未触及 / 触及 X 处已与用户确认
- 单遍 C2 扫描：0 触发
- 朗读 1 段：无卡顿

## Follow-up
- <无 / 列具体项>
```

---

## 边界案例

**多轮连续微调**：用户连续 3 轮提意见 → 每轮独立按本 SOP 处理；不要回溯合并。
**用户改主意撤回上轮修改**：直接 Edit 反向操作；不重读上一轮报告。
**用户要求"按 P0/P1/P2 顺序批量优化"**：每条按本 SOP 处理；可考虑并行启动子 agent（每条意见一个子 agent），主 agent 汇总。
