# 源材料清单协议 (Source Inventory Protocol, L0)

> **使用时机**：阶段二 B 分块计划之后、阶段二 C 翻译执行之前的**强制闸门**。**所有模式 C 任务开干前必做**（忠实翻译 / 改写转述 / 公众号改编 三个子模式通用）。
> **反陷阱**：**没有这份清单，main agent 不许翻译。** L0 的失败（编号错位 / 分类漏列 / 数字误读）会传导到 L1/L2/L3 全部层级。
> **2026-06-09 案例**：v1 翻译 30 prompts 时**未做源 dump**，main agent 凭"行业常识"补全 18/30 个原文不存在的 prompt 名（如把"Editing Assassin"译成"销售页面文案"），把 5 分类塌成 4 分类，漏译 prompt 20。**所有这些错误在源材料 dump 阶段就可见**——只要当时强制先列清单。

---

## 一、协议强制输出：3 张源材料清单

翻译开始前，main agent **必须**按以下格式输出 3 张清单，作为下游翻译的**合同**。**任一清单写不全或与原文对不上 → 翻译没开始 → 重新读源材料。**

### 清单 1：所有编号项目的【编号 / 原文标题】对

适用场景：源材料是「N. The XXX / NN. XXX / (1) XXX / 一、XXX / 第 N 章 XXX」等编号列表结构时。

```
源 dump — 编号列表
==================

清单 1.1：所有 N 个 [编号 + 英文原名] 对
1. The Viral Article Writer
2. The Thread Converter
3. The Headline Generator
4. The Email Copywriter
5. The Blog Post SEO Writer
6. The Social Media Repurposer
7. The Editing Assassin
8. The Caption and Hook Generator
9. The Deep Researcher
10. The Competitive Intelligence Analyst
...
N. The X

注：每行必须从源材料原样读出，禁止按"行业常识"补全。读不出来 → 标"读不出，需重读" → 重新读源材料。
```

### 清单 2：所有【分类 / 包含的编号】对

适用场景：源材料含「Section / 分类 / Chapter」等结构时。

```
源 dump — 分类结构
====================

清单 2.1：所有 [分类名 + 包含的 prompt 编号] 对
- Content and Writing: prompts 1-8 (8 个)
- Research and Analysis: prompts 9-14 (6 个)
- Business and Strategy: prompts 15-20 (6 个)
- Coding and Technical: prompts 21-26 (6 个)
- Personal Productivity: prompts 27-30 (4 个)

合计：5 分类 / 30 个 prompt

注：每个分类名必须从源材料原样读出。如果原文写 "Research and Analysis" 不得写"调研与分析"（译后名称不允许在这里出现，只许原版名称）。
```

### 清单 3：所有【数字 + 单位 + 上下文】对

适用场景：源材料含数字 / 时间 / 比例 / 金额 / 阈值时。

```
源 dump — 数字清单
====================

清单 3.1：所有 [数字 + 单位 + 上下文] 对
- 86% (相对提升) → 对应 CORE 78% vs 42% 差值
- 78% / 42% → CORE benchmark 分数
- 36 分 / 36-point → harness 间分差
- 15 万美元年薪 → 套壳 vs harness 工程师薪资差
- 5 折 → Batch API 折扣
- 90% → CLAUDE.md / system prompt 缓存节省
- 约 15 倍 → Multi-agent token 消耗倍率
- 57% / 89% / 32% → 行业现状百分比
- 30 个 prompt → 文章核心数字
- 17 周 / 40 周 → 全职/兼职学习时长
- 200 字 → 每日简报长度上限
- 280 字符 → 推文字数上限
- 150-250 字 → 邮件字数
- 1500 字 → 博客 SEO 文章字数
- 2500 字 → 爆款文章字数
- 100 字 → Instagram caption 长度
- 150-300 字 → LinkedIn post 长度
- 15 秒 → YouTube 钩子时长
- 30 天 → Open rates 时间窗
- ... (每出现一个数字都列)

注：每个数字必须从源材料原样读出。**禁止** "我记得大概是 X" "通常这类型文章写 Y 字" 等基于行业常识的补全。
```

### 清单 4（可选）：所有【专有名词 / 行业术语】对

适用场景：源材料含大量专有名词 / 行业术语 / 缩写时。

```
源 dump — 术语清单
====================

清单 4.1：所有 [专有名词 / 英文 / 上下文] 对
- Anthropic → 原文 §1, 出现 N 次
- Claude Code → §1 段 3
- Opus 4.5 → §1 benchmark 数据
- Claude Agent SDK → §1 工具栈
- LangGraph → §2 框架
- Deep Agents → §2 框架
- PostgresSaver → §2 持久化
- LangSmith → §2 观测
- ... (每出现一个专有名词都列)

注：禁止直译 jargon（如 "harness" 译为"马具"）。必查 cross-cultural-terms.md。
```

## 二、清单写完后的校验（4 项硬检查）

写完 3 张清单后，main agent **必须**对源材料做 4 项自检：

1. **完整性**：清单 1 包含的编号数 = 源材料中的所有编号（漏 1 个 → 重读源材料）
2. **分类不重叠**：清单 2 中每个 prompt 编号只属于 1 个分类
3. **数字穷尽**：清单 3 中每个数字都有上下文（"X%"的 X = ？，在哪里出现）
4. **原名保真**：清单 1/2 中的原文名称与源材料**逐字一致**（不缩写、不"改写"、不"规范"）

任一检查不通过 → 翻译**不允许**开始 → 回到源材料阅读。

## 三、清单的工程价值

| 维度 | 没清单的 v1 | 走清单的"理论 v0" |
|------|------------|------------------|
| 编号穷尽 | 漏译 #20 | 清单 1 写 30 个 → 漏 1 个立刻 catch |
| 名称 1:1 | 18/30 错位 | 清单 1 写原文名 → 翻译时直接对照 |
| 分类不漏 | 5 塌成 4 | 清单 2 显式 5 分类 → 强制 5 段 |
| 数字保真 | 漏 86% 加注 | 清单 3 显式所有数字 → 译时核对 |
| 翻译耗时 | 30-40 分钟 | 40-50 分钟（多 10 分钟给 dump） |
| 翻译质量 | L0 失败传染全层 | L0 干净 → 后续 4 层质量乘数 |

**ROI 计算**：多花 10 分钟 dump，换 18/30 错位 + 漏 #20 + 5→4 分类 这种**整篇返工级错误**不再发生。**ROI 100 倍以上**。

---

## 四、清单与下游环节的接口

清单 1/2/3 输出后，**所有下游环节都必须以清单为合同**：

| 下游环节 | 怎么用清单 |
|---------|----------|
| 阶段二 C 翻译执行 | 每 chunk 翻译时，对照清单 1 写编号清单 1.1 中对应行 |
| 阶段二 D 合并校验 | 校验 5 项小并到 1 项大时，重新对照清单 1 数编号 |
| 阶段二 E 后校验 | 5 段回译选段时，优先选清单 1 中 1/3/2/3 编号 |
| 阶段四 A 模式规则确认 | 引用清单 1 + 清单 2 的原文作为"已读凭证" |
| 阶段四 C1.5 subagent | 把清单 1/2/3 作为 subagent 的 reference 输入 |
| 公众号改编子模式 第 5 条 1:1 对账 | 清单 1 写出的 N×N 对账表 = 清单 1 + 翻译版的简单对比 |
| 阶段四 B 闸门 | 16 项闸门最后一项："清单 1/2/3 + 译文对照 N×N 表全过" |

---

## 五、何时跳过本协议

- **源材料不含编号列表结构**（如纯叙事文章 / 故事 / 散文）— 清单 1/2 跳过，清单 3 必做
- **源材料是单条短推文 / 单条段落** — 清单 1/2 跳过，清单 3 必做
- **源材料是音频转录稿** — 清单 1/2/3 全做（先按时间戳分段）
- **源材料是图片 / 截图** — 清单转为"图中的关键元素"清单

## 六、给 main agent 的执行 SOP

```
# 阶段 0：源材料清单 (L0)
1. Read 源材料（CDP 抓取 / 文件读入 / 用户粘贴）
2. 输出 3-4 张源材料清单（编号 / 分类 / 数字 / 术语）
3. 跑 4 项硬检查
4. 清单不通过 → 回到步骤 1 重读

# 阶段 1：5 阶段翻译管线（基于 L0 清单）
阶段一 模式判定 → 阶段 1.5 复杂度分流 → 阶段二 A 完整翻译预处理 → 阶段二 B 分块计划 → 阶段二 C 翻译执行（每 chunk 用清单 1 对照）→ 阶段二 D 合并校验（用清单 2）→ 阶段二 E 后校验 + 回译（用清单 3）

# 阶段 2：L1-L3 质量层
C2 grep（硬错）→ 资深编辑清单（软错）→ 公众号改编 8 大手法 → preflight → publish

# 阶段 3：阶段四 B 闸门
16 项闸门逐项过 → 全过 → 交付
```
