# 翻译交付前自查清单 (Translation Checklist)

> **使用时机**：翻译执行完成、进入后校验阶段时逐项打勾。全部通过方可交付。
> **前置必读**：翻译开始前必须读完 `translation-principles.md`。本 checklist 仅覆盖五条原则无法机械推导的硬事实项。

---

## 硬事实检查（不可逆/不可由原则推导）

- [ ] 固化英文词（LLM, RAG, Agent, Memory, Skills, Prompt, Token, MCP 等）已按规则保留
- [ ] 首次出现的保留词已按 `英文（中文释义）` 格式加注
- [ ] **Bilingual 术语全覆盖**：全文核心概念逐一回溯对账——每个在术语映射清单中登记的概念，首次出现均为 `中文（English）` 格式，后续章节统一裸用中文。漏一个标一个 ❌，对账表格式：`概念 | 首次位置 | 格式 | 通过/缺失`
- [ ] 同一概念全文译法/保留形式绝对统一
- [ ] 专有名词（TerminalBench/Ralph Loop/ACON/Magentic 等）首次出现已加注
- [ ] 原文技术细节（架构/数据流/模型行为/实验结论）100% 准确还原
- [ ] **数字语义验证：每个数字在中英文语境下表达同一个量吗？** 重点核查——倍数表述（"3x improvement"→"提升 3 倍"是原来的 3 倍还是 4 倍？）、百分比方向（"dropped by 80%"→"降低 80%"还是"降到 20%"?）、单位转换（英文单位在中文是否需要换算或加注？）、时间窗口是否压缩（"10 lunches / 10 seconds"三项全保留？）
- [ ] 未添加原文不存在的背景解释或主观评价
- [ ] 所有 fenced code block、inline code、CLI 命令、JSON/YAML、API 字段、Prompt 示例已逐字原样保留（详见 ai-translation-guide.md §4）
- [ ] 代码块内容未被翻译、重排、清洗、补全或格式化；疑似错误仅在代码块后用中文译注说明
- [ ] 标题、列表、引用、加粗/斜体与原文严格对齐
- [ ] 图表占位符已保留，无错位
- [ ] 链接、引用来源、作者信息完整保留
- [ ] 英文 Prompt 原文完整保留于独立代码块，未添加中文翻译
- [ ] 中英文混排已按"盘古之白"规则添加半角空格
- [ ] 排版规范已执行（全角引号/括号/破折号/货币格式）→ lint `check_ascii_quotes()` + `check_currency_format()` 自动检出；详细规则见 glossary-ai.md §11
- [ ] 回译验证已完成（低风险3段/高风险5段），全部通过无🔴

## 五条原则兜底检查

- [ ] **原则 A（结构脱钩）**：母语者朗读 3 段（开头/中间/结尾）无翻译腔卡顿？
- [ ] **原则 B（搭配对齐）**：抽检 5 对"动词+宾语"——在中文里能自然成组？
- [ ] **原则 C（密度对齐）**："的"≥3 次或主语-谓语 ≥15 字的长句已拆分？
- [ ] **语气不越界**：中文本地化未增强原文没有的情绪、判断、确定性或立场？
- [ ] **Punchy Style** 仅用于 X/Twitter/Substack/独立作者短文；正式报告、长访谈、技术文未误用？
- [ ] **主语锁定**：英文祈使句 / 模糊主语（"Don't worry, I break it down" / "You are the loop"）译成中文后，动作发出者是否明确？"我还不知道"≠"你还没看懂"——主语反转是最常见的逻辑断层。抽检 3 处含隐含主语的段落，确认中文主语与原文一致。
- [ ] **短句主语完整性**：≤5 字的中文短句（如"挂了。""断了。""到了。"），如果脱离上下文无法独立理解，必须补主语（"测试挂了。""链接断了。""目标到了。"）。朗读检验：遮住前文，这句话单独成立吗？
- [ ] **语域漂移**（原则 D）→ lint `check_register_drift()` 自动检出；详细规则见 translation-principles.md 原则 D
- [ ] **隐喻对等映射**（原则 E）→ lint `check_collocation_traps()` 检出常见陷阱；详细规则见 translation-principles.md 原则 E
- [ ] **拟人化/具象动词回落**（原则 B/E）：扫描"长大/牵着走/吃掉/躺在/奔跑"等描述人或物理物件的动词被用在抽象流程/技术概念上 → 回退到术语或书面表述（"技术长大"→"技术栈扩展"，"被牵着走"→"高度依赖"）。判定：遮住宾语，这个动作只能由人或物理物件做出 → 回落。详细映射见 translation-quickref 原则 D（2026-08-25）
- [ ] **英文夹杂**→ lint `check_untranslated_english()` 自动检出中文行文中未翻译的英文动词/形容词（人名/公司名/技术缩写自动跳过）
- [ ] **介词链冗余**→ lint `check_preposition_chain()` 检出"在...在...在"≥3 次的语法冗余
- [ ] **机翻句式**→ lint `check_is_about_pattern()` 检出"X 是关于 Y"（英文 "is about" 直译）
- [ ] **术语一致性**→ lint `check_term_consistency()` 检出同一英文词在译文中的多种译法

## 格式与规范

- [ ] frontmatter.title 与正文一级标题一致
- [ ] 文章内图片已本地化 + 相对路径引用
- [ ] 来源链接裸 URL 单独成行
- [ ] **代码块语言标签**：每个 fenced code block 必须标注语言 → lint 自动检出
- [ ] **CLI 命令/斜杠命令行内代码格式**：正文中 `/goal`、`/loop` 等命令名用 `` ` `` 包裹 → lint 自动检出
- [ ] **指代具体化**：遇到"那种""这个""某个"等模糊指代修饰英文术语时，检查是否可以补出具体语境让读者不用猜。判断标准：遮住上下文，读者能猜到"那种"指的是什么吗？

## 交付物清单对齐（硬阻断，不通过不可进入阶段三）

> lint `check_delivery_alignment()` 自动执行。源文件为非 markdown 格式（如 youmind 纯文本提取）时，代码块/标题检查自动跳过以避免假阳性。

| # | 检查项 | 条件 |
|---|--------|------|
| 1 | 代码块数量 | 源译文均有 ` ``` ` 时比对 |
| 2 | 图片引用数量 | 源有图片（`![]()` 或裸 URL）且译文有 `![]()` 时比对 |
| 3 | 章节标题数量 | 源译文均有 `##` 时比对（允许 ±1） |

输出：`代码块 X/X | 图片 Y/Y | 章节 Z/Z`。任一不对齐 → 补齐后再走。

## 反馈闭环

- [ ] 记录本次"不确定/查资料/讨论"的术语，登记至 `glossary-ai.md` 待定区
- [ ] 摘录 1-2 个"优化前后对比"片段存入 `examples/translation/`
- [ ] 发现新搭配越界/结构脱钩案例→补入 `translation-principles.md` 对应原则（只加案例，不加规则）
- [ ] 标注流程中卡点/模糊点，月初复查对齐

## 流程合规性

- [ ] 英文源材料已完成轻审计闸门；高风险材料已升级完整审计
- [ ] 已完成忠实翻译后再进入目标模式改写，未跳过翻译直接提炼重写
- [ ] 术语争议（如有）已按仲裁流程处理并记录至 `glossary-ai.md`
- [ ] 翻译前已读 `translation-principles.md` 三条原则
- [ ] 目标模式改写完成后，已完成"改写版 vs 忠实翻译版"事实断言差异检查，无信息丢失或扭曲
