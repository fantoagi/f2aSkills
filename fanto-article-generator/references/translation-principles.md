# 英文中译三条元原则

> **定位**：翻译执行的"操作系统"。不需要记 130 条规则，每句翻译时过 3 个问题即可。
> **加载时机**：翻译开始前必读。与 `translation-quickref.md`（模式速查）、`glossary-ai.md`（术语）配合使用。
> **维护规则**：发现新问题后补充案例到对应原则下，不加新规则条目。

---

## 原则 A：中文不说英文的结构

**判断**：这句译文的结构是从英文句式直接搬过来的吗？

**检查点**：
- `because` → `因为` 直译？（改用"之所以/关键在于/不同之处在于"或破折号拆因果）
- `and` 开头串联段落？（直接砍掉或用"但/而"）
- `X is not just about Y` → `X 不仅是关于 Y`？（删 `about`，`X 不只是 Y，更是 Z`）
- `This is why` → `这就是为什么`？（`正因如此` / `所以`）
- `the fact that` → `……这一事实`？（删掉，改写为主谓结构）
- `It turns out that` → `事实证明`？（`实际上` / `原来`）
- `key insight` → `关键的洞察`？（`关键在于` / `核心在于`）
- `X is the bridge/link/hinge between A and B` → `X 是 A 和 B 之间的桥/纽带/铰链`？（中文不用建筑/机械零件做抽象连接比喻。改用动词式：`X 把 A 和 B 串了起来`）
- `after + 名词短语` → `在 + 名词堆 + 后`？（"在……后"框架内必须含主谓结构。`在大量实验证据积累后` ❌ → `在他积累大量实验证据后` ✅）
- 英文名词句制造停顿（`Simple idea. Insane at scale.`）照搬为中文名词句？（恢复为主谓结构：`想法很简单。规模上来就惊人。`）
- 单句内"其/该/此"连续 ≥2 次？（删掉或换"它/这/那"——中文靠零代词回指,不靠书面代词）

**经典案例**：

| 原文模式 | ❌ 结构照搬 | ✅ 中文重组 |
|:---|:---|:---|
| `This is why students feel...` | 这就是为什么学生会觉得 | 学生会觉得……就是这个原因 |
| `after he accumulated evidence` | 在大量实验证据积累后 | 在他积累大量实验证据后 |
| `X is the bridge between A and B` | X 是 A 和 B 之间的桥 | X 把 A 和 B 串了起来 |
| `A reminder: ...` | 一个提醒：…… | 需要提醒的是：…… |
| `Don't worry, I break it down below`（隐含主语：I=作者） | 别急，我还不知道是什么意思（主语反转为作者不懂） | 别急，如果你还没看懂，我们稍后逐一拆解 |
| `You are the loop`（祈使/判断句） | 你就是循环（直译无误但可强化） | 你就是那个循环——每次都是你在检查工作 |
| `It breaks.`（≤5 字短句，主语省略） | 挂了。（遮住前文不知道什么挂了） | 测试挂了。（补主语，短句独立可理解） |

> **口诀**：遮住英文原文，只读中文译文。句子读起来像"翻译过来的" → 结构被英文牵着走了 → 拆掉英文句式，用中文重新说一遍。

## 原则 B：中文的词有自己的搭配边界

**判断**：动词+宾语、形容词+名词、量词+名词——这三个"词对"在中文里能自然成组吗？

**检查点**：
- 动词+抽象宾语：`cut through` + 研究 → `穿过` ❌（`贯穿` ✅）。`spend` + 注意力 → `花掉` ❌（`耗费` ✅）。`offload` + 认知任务 → `卸载` ❌（`交由` ✅）。`walk into` + 对话 → `走进` ❌（`面对` ✅）
- 量词+抽象名词：`equivalent` + 理解 → `等量的理解` ❌（`相应的理解` ✅）
- 程度副词+二值动词：`部分卸载` ❌（二值动词天然排斥程度修饰。"卸载"是 on/off，"部分关闭"说不通）
- 空间动词+抽象宾语：`穿过/走进/踏入` 的宾语必须是物理空间，不能是论文/实验/对话
- **物理动词+抽象宾语**：`拉/推/拽/抬` 的语义锚点在物理施力——宾语是数字/营收/价格等抽象概念时，改用`增至/跃升至/推高至`。`从300亿拉到470亿` ❌ → `从300亿增至470亿` ✅
- **固定搭配拆解重组**：中文复合词的组成语素不能像英文词根一样拆出来独立使用。`双头垄断`→`双头格局` ❌（`双头`的语义锚点只在"双头垄断"里存在。改`两强并立`）。`开源模型`→`开源的XX` ✅（`开源`本身已是完整形容词，可以独立搭配）
- 研发语境：`cold` → `冷` ❌（`冷启动` ✅）。`flip` → `翻转` ❌（`切到/设为` ✅）。`bursts` → `脉冲` ❌（`突发流量` ✅）
- **高保真锚点（数字+具体物+时间窗口）**：原文同时出现具体数字 + 具体物体 + 时间窗口的组合时（`$1000 / single task`、`10 lunches / 10 seconds`、`50-100 dollars / month`），三项必须原样保留，不得替换意象。可调整语法让中文通顺，不得改换数字、物体或压缩时间关系。此规则特别针对隐喻翻译——英文用日常物品做计量单位（午餐、咖啡、电影票）是故意为之，替换为中文读者更熟悉的意象会导致数字精度和原文语感双重丢失
- **比喻载体拆解**：英文用非中文读者熟知的领域术语做比喻载体时（如 `hill climbing machine`），**不把"术语"和"比喻载体"压成一个中文生造词**。用 `"术语" + 比喻载体` 的引号拆解格式：`"爬山"机器` = 爬山（优化算法）+ 机器（比喻载体）。读者的理解路径：先通过引号认出"爬山"是算法术语 → 再理解"机器"是比喻。反例：`hill climbing machine→"爬山机"` ❌（生造词，中文读者第一反应是健身器材）

**经典案例**：

| 动词+宾语 | ❌ 搭配越界 | ✅ 自然搭配 |
|:---|:---|:---|
| `cut through + research` | 穿过两篇研究 | 贯穿了两篇研究 |
| `spend + attention` | 花掉注意力 | 耗费注意力 |
| `offload + cognitive tasks` | 卸载认知任务 | 交由它处理 |
| `equivalent + understanding` | 等量的理解 | 相应的理解 |
| `10 lunches in 10 seconds` | 整月福利和一顿免费午餐的区别 | 10 秒钟内烧掉相当于 10 顿午餐的钱 |
| `recover + gap` | 恢复差距 | 弥合差距 |

> **口诀**：遮住动词/形容词/量词之外的全部修饰语，只看"X+Y"两个词——"穿过+研究"？"花+注意力"？"等量+理解"？不能成组 → 搭配越界 → 换词，不要加定语来凑。

## 原则 C：中文的信息密度靠短句和显式逻辑，不靠长定语

**判断**：读一遍译文——主语在哪？读到一半还记得主语吗？

**检查点**：
- 单句"的"字连续 ≥3 次？（必须拆分）
- 主语与第一个谓语之间相隔 ≥15 字？（修饰前置太长，调语序或拆分）
- 一个中文句包含 ≥2 个"which/that/where"层的英文嵌套被翻译为逗号拼接？（拆为独立短句）
- 英文被动语态直译后堆了大量"被/进行/作出/加以"？（转主动，删冗余词）
- 英文多层定语从句（`A that does B by doing C through D`）被塞进一本中文书里？（倒序拆分：`A 通过 D 完成 C，从而实现 B`）

**经典案例**：

| 原文结构 | ❌ 长定语堆叠 | ✅ 短句拆分 |
|:---|:---|:---|
| `X, which does Y, where Z happens` | X 负责 Y，其中 Z 会发生（读到"其中"忘了主语） | X 负责 Y。在 X 内部，Z 会发生 |
| 3 个"的"连续 | 采用了在多个硬件平台上都能运行的、由社区维护的、开源的编译器 | 这个编译器开源、由社区维护，能在多个硬件平台上运行 |

> **口诀**：拆分后只读"主语 + 谓语 + 宾语"，意思完整吗？不完整 → 修饰离主语太远，得调语序。

## 原则 D：语域分级——口语化 ≠ 俗语化

**判断**：这句译文是"说给朋友听的自然表达"，还是"菜市场/酒桌/游戏里的俗语"？

**问题背景**：Mode C 要求"中文口语化但正式"，但"口语化"常被误读为"可以用任何俗语/俚语/网络梗"。实际上：
- ✅ **允许的口语化**：去掉书面腔（"进行""加以""作出"）、缩短主语-谓语距离、用主动句、用"就是/就是"而非"即是"
- ❌ **禁止的俗语化**：菜市场用语（"零头""便宜货"）、游戏/体育俗语（"下场打球""送人头""躺赢"）、拟人化情绪（"手太松了""脑子进水了"）

**分级规则**：

| 语域级别 | 适用场景 | 示例 |
|:---|:---|:---|
| L1 正式书面 | 学术论文、白皮书 | "该模型在基准测试中表现优异" |
| **L2 专业口语（Mode C 目标）** | 公众号技术文章、开发者社区 | "这个模型跑分很强" |
| L3 日常俗语 | 朋友圈、群聊吹水 | "这模型牛逼炸了" |

Mode C 锁定 **L2 专业口语**——像资深工程师在技术分享会上说话，不是在大排档吹牛。

**检查点**：
- **拟人化情绪**：给模型/系统赋予人类情绪或身体反应 → 检查是否越界
  - ❌ "手太松了"（给模型赋予了人类打分的身体动作 + 情绪判断）
  - ✅ "标准往往过于宽泛"（客观描述）
  - ❌ "模型自己都想哭" → ✅ "模型的输出质量明显下降"
- **俗语/俚语**：来自菜市场/游戏/体育/酒桌的比喻
  - ❌ "零头"（菜市场语境描述成本）→ ✅ "极低的开销"
  - ❌ "下场打球"（体育俗语描述执行）→ ✅ "亲自介入执行"
  - ❌ "送人头"（游戏俗语描述失败）→ ✅ "产生无效输出"
- **保留的好口语**：不降格为俗语，但去掉了书面腔
  - ✅ "微操"（游戏术语但已进入技术圈通用语，形容精细操控）
  - ⚠️ "跑分"——体裁敏感词。公众号/社交媒体可接受；工程博客/技术复盘**必须替换为"基准测试"**
  - ✅ "造出这些工具的人"（口语化但不俗）
- **改写阶段自产比喻的语域通胀（Rewrite-Stage Metaphor Inflation）**：
  此条针对模式 C/D 改写阶段新增的、源材料中不存在的比喻——不是翻译腔，是"改写者试图匹配源材料的修辞能量但用力过猛"。触发机制：源材料使用了强比喻（如火、电、沙子思考、奇迹），改写者在转述时追加自己的比喻来"竞艳"，这些自产比喻系统性越过 L2→L3。
  - ❌ "他开篇第一句话就让所有人停下了拇指"（源材料无此比喻，自产"停下拇指"=L3 媒体自嗨黑话）→ ✅ "他开篇的论断，足以让整个行业屏息"
  - ❌ "大家都刹一脚"（源材料 slowdown 非刹车比喻，自产"刹一脚"=L3 口语）→ ✅ "集体降速"
  - ❌ "监管的矛头只对准最头部的那几家"（源材料无武器比喻，自产"矛头"=L3 暴力隐喻通胀）→ ✅ "监管焦点只对准最头部的那几家"
  判断标准：遮住中文，这句里的比喻（动词/名词画面感）在源材料里有对应吗？没有 → 这是改写者自产比喻 → 问一句：这个比喻是"技术分享会上会说的话"吗？不是 → 降为直述。

**口诀**：遮住原文，只读中文。这句话像技术分享会上说的话 → ✅。像大排档吹牛 → ❌。像论文 → 太正式，调松一点。

## 原则 E：隐喻对等映射——直译 ≠ 传神

**判断**：英文隐喻直译后，中文读者感受到的画面/情感/语义色彩，和原文读者一样吗？

**问题背景**：英文 tech 写作大量使用隐喻（"dialect""locked in""paste your life into a chat box"）。这些隐喻在英文中精准传神，但直译成中文后常常出现三种问题：

| 失败类型 | 机制 | 示例 |
|:---|:---|:---|
| **语义偏移** | 同一个隐喻在中文里携带不同的情感色彩 | "dialect"（中性/巧妙）→ "方言"（暗示"土/非正式"） |
| **搭配不可迁移** | 隐喻中的动词+宾语在中文里不构成自然搭配 | "paste your life into a chat box" → "把生活粘贴进聊天框"（"粘贴"的宾语不能是"生活"） |
| **语境不对等** | 英文隐喻在 tech 语境已固化，中文尚无对等隐喻 | "locked in"（vendor lock-in，tech 圈通用）→ "被锁定"（听起来像门禁系统） |

**处理规则**：

1. **优先找中文等效隐喻**：有没有一个中文隐喻传达同样的画面感？
   - "paste your life into a chat box" → "反复把背景复制给 AI"（直述，不硬造隐喻）
   - "dialect" → "语法 / 写法"（放弃隐喻，用直述，因为中文没有对等的"方言"隐喻）
2. **没有等效隐喻时，直述优于硬造**：不要为了保留原文的修辞效果而生造中文读者不理解的隐喻
   - "locked in" → "不被任何平台绑死"（tech 圈惯用表达）
   - ❌ "你不会被锁在笼子里"（硬造隐喻，中文读者困惑）
3. **已固化的英文 tech 隐喻，用中文 tech 惯用表达替换**：
   - "vendor lock-in" → "供应商锁定风险 / 平台绑定"
   - "free tier" → "免费版"（不是"免费层"）
   - "bootstrapping" → "自举"（已固化的技术术语）

**检查方法**：遮住原文，读中文。这句话的**画面感**和原文读者感受到的一样吗？如果中文读者脑中浮现的画面和英文读者完全不同 → 隐喻映射失败 → 替换或直述。

**经典案例**：

| 原文隐喻 | ❌ 直译 | ✅ 对等映射 |
|:---|:---|:---|
| "paste your life into a chat box" | 把生活粘贴进聊天框 | 反复向 AI 复述自己的背景 |
| "Teach Claude the Obsidian dialect" | 教 Claude Obsidian 方言 | 教 Claude Obsidian 语法 |
| "you stay unlocked" | 你不会被锁定 | 不被任何平台绑死 |
| "the free tier" | 免费层 | 免费版 |
| "a knowledge engine" | 知识机器 | 知识引擎（"引擎"在中文 tech 语境已固化为隐喻） |

> **口诀**：英文隐喻是画面，中文也要有画面。直译后画面碎了 → 不要粘碎片，换一幅完整的。

## 原则 F：工程文档动词升级——技术复盘不是社交媒体

**触发条件**：阶段 1.2 体裁识别判定为「工程博客/技术复盘」或「学术论文/评测」时强制启用。其他体裁跳过本条。

**判断**：这句译文的动词，在 An Anthropic/Vercel/Linear 工程师写的 Post-mortem 里会出现吗？

**问题背景**：翻译管线默认目标是"微信公众号技术文章"（L2 专业口语），但工程博客/技术复盘是**工程师写给工程师看的**——它的口语不是"公众号口语"，而是"代码审查评论区口语"。这两者的动词选择有系统性偏差：

| 公众号 L2 口语 | 工程博客口语 |
|:---|:---|
| "这个模型跑分很强" | "该模型在基准测试中表现突出" |
| "Agent 跑偏了" | "Agent 行为偏离预期" |
| "把服务干崩了" | "导致服务瘫痪/不可用" |
| "先在假数据上跑" | "先在脱敏数据上运行" |

**工程博客禁用动词清单**（翻译执行阶段逐句检索，命中即替换）：

| # | ❌ 禁用 | ✅ 工程文档替换 | 说明 |
|:---|:---|:---|:---|
| 1 | 干崩 / 搞崩 / 弄挂 | 瘫痪 / 导致……不可用 / 引发服务中断 | 工程事故不用"干/搞/弄"系动词 |
| 2 | 跑（CLI/脚本/命令） | 执行 / 运行 | CLI 操作的标准动词 |
| 3 | 跑偏 / 跑飞 | 行为偏离预期 / 产生非预期输出 | "跑偏"是口语方向词 |
| 4 | 跑分 | 基准测试 / 评测 | 工程文档不用手机圈黑话 |
| 5 | 坐（在沙箱外/在进程里） | 驻留 / 运行于 / 部署在 | 系统组件的空间位置不用"坐" |
| 6 | 捡起 / 捡到 / 抓到 | 读取 / 检测到 / 捕获 | Payload/信号的获取是"读取"不是"捡" |
| 7 | 长得一样 / 一个样 | 如出一辙 / 结构相同 / 逻辑一致 | 代码/架构的相似性不用外貌词 |
| 8 | 答错 / 搞错 | 误判 / 做出错误决策 | 工程决策的失败模式是"误判" |
| 9 | 平移 / 搬过去 | 移植（port）/ 迁移 / 照搬 | 软件跨平台用"移植" |
| 10 | 假数据 | 脱敏数据 / 模拟数据 / 合成数据 | 安全工程语境中"假"不精确 |
| 11 | 弥漫 | 散布 / 存在于 / 残留于 | Payload 在系统中的分布不用感官动词 |
| 12 | 打偏 / 打不中 | 落空 / 未命中 / 未能拦截 | 防御机制的失败是"落空" |
| 13 | 压住 / 按住 | 收束 / 控制 / 限制 | 爆炸半径的管控是"收束" |
| 14 | 塞进 / 丢进 / 扔进 | 写入 / 输入 / 导入 | 数据进入系统不用暴力动词 |

## 交付前兜底：三道机械扫描

写作/翻译完成后，逐句执行三轮扫描。注意：不靠"读起来顺不顺"的直觉——写作和朗读共享同一盲区。靠机械条件触发。

### 第一遍：结构扫描（原则 A）

逐句问：
- 句首是 `因为`/`而且`/`并且`？→ 砍掉或换 而/但
- 句首是 `这就是为什么`/`事实证明`/`关键的洞察是`？→ grep 式替换
- `在……后` 框架内只有名词堆、没有主谓结构？→ 补主语+动词或换"经过"
- 单句内 `其/该/此` ≥2 次？→ 删掉或换 它/这
- 名词句独立成段但无主谓？（`简单的想法。可怕的规模。`）→ 恢复为主谓结构

### 第二遍：搭配扫描（原则 B）

逐句找到每个动词，做两步检查：

第一步：**剥掉修饰语，只看裸动词+宾语**
- `从 300 亿 [拉到] 470 亿` → 遮住"从300亿"和"470亿" → `拉`。`拉` 是物理拖拽动作，宾语是数字 → 越界 → `增至`
- `[确立] 双头格局` → 遮住修饰 → `确立+格局` ✅（可以成组）。但 `双头+格局` → `双头` 的锚点只在"双头垄断"中 → 拆解重组越界 → `两强并立`

第二步：**判断动词的语义锚点**
- 物理施力类（拉/推/拽/抬/拎）→ 宾语必须是物理对象。数字/营收/价格 ❌
- 空间移动类（穿过/走进/踏入/步入）→ 宾语必须是物理空间。研究/论文/对话 ❌
- 安装/拆除类（卸载/装载/装配）→ 对象必须是实体组件。认知任务/工作 ❌
- 程度副词 + 二值动词（部分卸载/部分删除/部分关闭）→ ❌

### 第三遍：密度扫描（原则 C）

逐句检查：
- `的` 出现 ≥3 次 → 拆分
- 主语到谓语的距离 ≥15 字 → 调语序或拆分
- `被`/`进行`/`作出`/`加以` 连续出现 → 转主动、删冗余

### 扫完后

> 发现任何一个机械条件被触发 → 改写。三类扫描全部通过 → 交付。

每发现一个机械扫描覆盖不到的新问题，补到对应原则文件中作为新案例，**不加新规则条目**。

### 第五遍：语义真值扫描（原则 A/B/C/D 均不覆盖的盲区）

前三遍机械扫描覆盖结构/搭配/密度，第四遍覆盖输入法残留——但**没有任何一遍检查"字面意思对不对"**。这是系统性盲区：大脑读到数字/量词/时间/因果时会自动切换为"修辞模式"，跳過数学校验。

**扫描对象**：全文所有含数字、量词、时间窗口、因果/对比关系的陈述句。

**检查方法**——逐句问三个问题：

1. **数字字面真值**：句中的数字陈述，按字面数学含义计算，成立吗？
   - `"从 Prompt 到 Loop，表面上是三个字母的差距"` → Prompt=6 字母，Loop=4 字母 → ❌ 不存在"三"的数学关系
   - `"提升了 3 倍"` vs 原文 `"3x"` → 中文"提升 3 倍"= 变成 4 倍 → 核实原文是 3x（3 倍）还是 4x（4 倍）
   - `"降了 3 倍"` → 中文"倍"只用于增，降用"降到原来的 1/3" → ❌

2. **时间窗口压缩**：句中的时间关系，和原文一致吗？
   - `"一个晚上之前…一个晚上之后"` → 原文是"一个晚上"的转变还是"一个渐进过程"的压缩？

3. **因果方向**：A 导致 B 的因果箭头，和原文一致吗？
   - `"因为 X 所以 Y"` → 遮住"因为/所以"，只看 X 和 Y 的命题 → X 真的能推出 Y 吗？

**触发后的处理**：
- 数字字面不成立 → 替换为精确陈述（不用"三个字母"，用"一个词"或具体数字）
- 时间窗口被压缩 → 恢复原文的时间尺度
- 因果方向存疑 → 回原文验证

**为什么这是"第五遍"而非嵌入前四遍**：前四遍都是机械模式匹配（grep 就能做）。语义真值扫描需要**逐句暂停 + 字面理解 + 数学验算**——这是唯一一步不能靠脚本、必须人肉执行的扫描。但它也只需要 2-3 分钟：全文标记所有含数字/量词的句子，逐句验算。

> **反例**（2026-07-08 实测）：`"从 Prompt 到 Loop，表面上是三个字母的差距"` 贯穿了初审、C2 扫描（5 道机械扫描）、C3 朗读、两轮人工审校共 5 道防线全部漏过。根因：大脑将"三个字母"自动解析为修辞（"差几个字母"≈"没差多少"），不做数学校验。此类 Bug 的检出只能靠语义真值扫描。
