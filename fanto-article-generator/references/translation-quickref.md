# 翻译规则速查表 (Quick Reference)

> **定位**：按五条原则分组的"模式→变换"速查表。原则本身见 `translation-principles.md`，术语见 `glossary-ai.md`。
> **使用**：翻译中遇到具体模式时快速查替换方案，不需要记忆。

## 原则 A：结构脱钩 — 模式速查

| 英文模式 | ❌ 结构照搬 | ✅ 中文重组 |
|:---|:---|:---|
| `This is why...` | 这就是为什么 | 正因如此 / 所以 / ——这就是……的原因 |
| `the fact that...` | ……这一事实 | 删掉，改写为主谓结构 |
| `It turns out that...` | 事实证明 | 实际上 / 原来 / 结果发现 |
| `key insight is that...` | 关键的洞察是 | 关键在于 / 核心在于 |
| `X is not just about Y, it's about Z` | X 不仅是关于 Y | X 不只是 Y，更是 Z |
| `X is the bridge/link/hinge between A and B` | X 是 A 和 B 之间的桥 | X 把 A 和 B 串了起来 |
| `after + noun phrase` | 在 + 名词堆 + 后 | 在 + 主谓 + 后 / 经过 + 名词 |
| `Simple idea. Insane at scale.` | 简单的想法。可怕的规模效应。 | 想法很简单。规模上来就惊人。 |
| `And` 开头 | 而且 / 并且 | 砍掉，或用 而/但 |
| `because` 在科普文体 | 因为 | 之所以 / 不同之处在于 / 关键在于 |
| `its/this/that/which` 连续 | 其/该/此 堆砌 | 删掉或换 它/这/那；中文靠零代词回指 |
| 英文换行暗示转折 | 无连接词 | 用 而/但/却 显式连接 |
| `What actually [verb]`（标题/问句） | 实际上[verb]了什么 | 到底[verb]了什么 |
| `N-second version`（标题括号注） | N秒版 | N秒速览 |
| `not because...but because...`（长句） | 不是因为……而是因为…… | 并非因为……而是…… |
| `can't believe / it's like / like`（表 disbelief） | 不觉得 / 不应该 | 竟然要…… / 居然要……（原文是"不敢相信"，不是"不同意"，用"居然/竟然"还原 shock 语气，不用"不觉得"） |
| `ship from X and Y`（产品/模型发布语境） | 从 X 和 Y 中发布 | X 与 Y 陆续发布 / 来自 X 和 Y 的新一代模型（"从…中发布"是英文介词框架直译，中文动词"发布"不需要"从…中"包裹来源） |
| `underneath / underlying` | 抽象层级关系 | 下面的 X | X 本身 / 底层 X（"下面的"在中文是物理方位如"桌子下面"；"underlying"=底层/本质，不是空间位置） |
| `at scale`（工程/商业语境，如"multi-physics simulation at scale"） | 大规模场景 | 在大规模下 | 在处理大规模场景时 / 规模化后。"在大规模下"是英文介词框架 `at scale` 的直译——中文"在…下"框架内需要完整名词短语。同类：`over time→在时间里`→随时间；`at scale→在大规模下`→规模化后 |
| `becomes very + adj`（如 tactical） | 状态变化 | 变得很战术 | 落到战术层面 / 变成了具体选择（英文形容词结构直译，中文"战术"不作形容词谓语的补足语） |
| `comes less from X than from Y` | 更多不来自 X，而来自 Y | 核心不在于 X，而在于 Y / 与其说来自 X，不如说来自 Y（"更多不来自"是英文比较结构直译，中文不这么说） |
| `exactly what X requires` | X 所需的全部 | X 所需要的（"全部"是英文强调结构的冗余迁移，"exactly"不需要译成"全部"） |
| `with X advantages, [walking the same road]` | 带着 X 优势走在同一条路上 | 有着 X 优势 / 凭借 X 优势（"带着优势走在路上"是英文伴随结构的直译，中文不把"优势"当随身物品） |
| `What's X? Y.`（英文设问制造停顿） | X 是什么？Y。 | 结果就是：Y / Y（中文不需要设问来制造停顿——删设问，直接陈述结论。英文"What's the result? You're still the bottleneck."→"结果就是：你反而成了效率瓶颈。"，不写"结果是什么？你是瓶颈。"） |
| `That's the whole thing / The whole process is like this`（英文收尾惯用语） | 整件事就是如此 / 整个流程就是这样 | 这套方案的核心逻辑就这么简单 / 核心逻辑一句话就能说清（英文用总结式收尾句制造段落节奏，中文直译成"整件事就是如此"像在翻译说明书。改用"核心逻辑"+"简单"的递归结构，既总结又不生硬） |
| `there` 作句法占位词（非地点，如 `why each expert is there`） | 在那里 / 在那儿 | 删除或替换为具体指代。`why each expert is there`→"为什么需要这个角色/这个专家的入选理由"，不译"为什么每个专家在那里"。"there"在此是英文句法填充词（dummy subject 的远方亲戚），中文必须补全实际语义 |
| `X is the bottleneck`（抽象隐喻直译） | X 是瓶颈 | X 反而成了效率瓶颈 / X 拖慢了整个系统（"是瓶颈"在中文过于抽象——什么瓶颈？谁的瓶颈？英文 bottleneck 已是标准化隐喻，中文需补一句"效率"或"系统"做锚定。`You are still the bottleneck`→"你反而成了整个系统的效率瓶颈"） |
| `say + 状态码/判定词`（如 `say BLOCK`、`say SHIP`） | 说 BLOCK / 说 SHIP | 直接打回（BLOCK）/ 直接通过（SHIP）。英文 `say + 判定词` 是口语化表达，中文代码审查/技术决策语境中，"说 X"像在口头表态而非正式裁决。改用动词：`say BLOCK`→"直接打回（BLOCK）"，`say SHIP`→"标记通过"。保留英文缩写加中文动词做锚定 |

### 排版铁律（盘古之白）

| 场景 | 规则 | 示例 |
|:---|:---|:---|
| 中文 + 英文/数字 | **默认保留一个半角空格**（公众号改编形态）——2026-08-10 用户以"严格执行"指令全局反转旧"不加空格"偏好（AI Adoption 文章 A 轮审校后 5 轮未再出现空格问题） | `Token 预算`、`GitHub 早期投资人`、`5 年 3 家` |
| 中文 + 全角标点 | 不加空格 | `使用 Agent，而不是` |
| 百分比/数字区间 | 区间写全：`N% - M%`（百分号保留、区间两侧半角空格），不写缩写 `N-M%` | `5% - 10%`、`2020 - 2025`（2026-08-10 C3 轮：`5-10%` 打回） |
| 中文句中独立英文术语 | 首字母大写（作为主语/核心名词时）**且全文大小写绝对一致**——同一术语 token/Token、专名 vas/Vas 混用是硬错误，定稿前全局核对（c2_scan.py 扫描 11 机械覆盖专名大小写） | `Token 成本`、`Coding Agent`、`Headless 方式`；但引语中的口语化小写保留（`"你随手丢给 agent 一个任务"` 中 agent 可小写） |

## 原则 B：搭配对齐 — 模式速查

### 通用动词跨域搭配

| 英文 | 宾语类型 | ❌ | ✅ |
|:---|:---|:---|:---|
| `cut through` | 内容/论证 | 穿过研究 | 贯穿 / 快速梳理 |
| `spend` | 注意力/心力 | 花掉注意力 | 耗费 / 投入 |
| `offload` | 认知/工作 | 卸载任务 | 交由处理 / 外包给 |
| `walk into` | 抽象处境 | 走进对话 | 面对 / 陷入 |
| `equivalent + N` | 抽象名词 | 等量的理解 | 相应的理解 |
| `come for / go after` | 市场/地盘（商业语境） | 扑向 / 冲向 | 抢占 / 吃下 / 吞掉（"扑向"是捕食动词，商业语境搭配越界） |
| `internalize + shape` | 问题/业务形态 | 内化了形状 | 摸透了形状 / 吃透了形态（"内化"在中文只能搭配抽象名词如知识/经验/价值观，不能搭配物理名词"形状"） |
| `narrow + piece/slice` | 工作任务/子任务 | 狭窄环节 / 狭窄切片 | 垂直领域 / 细分环节（"狭窄"在中文有负面含义如"心胸狭窄"，商业语境中"narrow"=聚焦/细分，不是贬义） |
| `live + in + 抽象容器` | 逻辑/数据/规则 | 住在规则引擎里 | 封装在 / 存在于 / 由…来承载（"住"在中文主语只能是人或动物，逻辑不能"住"在引擎里） |
| `put X on it / put people on it`（部署/分配语境，如"先 prototype，把人放上去"） | 人员/用户部署 | 把 X 放上去 | 拉 X 进来跑 / 让 X 先用起来。"放上去"是英文 `put X on it` 的空间动词直译——中文产研圈的惯用说法是"拉进来跑/让内部先用/推给用户测"，不需要"放"这个物理动作。 |
| `exert + power/control` | 权力/控制 | 施加权力 | 行使 / 掌握（"施加"搭配压力/影响，不能搭配权力或控制力） |
| `施加 + N` | 权力/影响力 | 施加定价权 | 行使定价权 / 掌握定价权 / 拥有定价权（"施加"只与压力/影响/负担成组） |
| `evolve + N`（及物） | 流程/系统 | 演进工作流 | 迭代 / 持续改进（"演进"是不及物动词，东西自己演进，你不能去"演进"它） |
| `一场 + N` | 抽象物 | 一场清醒剂 | 一剂清醒剂 / 一篇冷静的分析（"场"搭配事件如雨/对话/比赛，不搭配物；量词须匹配名词类别） |
| `stay in the loop` | 决策/审批/流程 | 留在环内 | 在决策链路里 / 参与决策（"留在环内"是英文习语直译，中文读者看到"环"不知道是什么） |
| `happy path breaks` | 软件/流程 | 正常路径断裂 | 标准流程走不通 / 主路径断了（"断裂"在中文是物理破坏如骨折/断裂带，不用于软件流程） |
| `production usage` | 软件/系统 | 生产使用 | 真实业务中运行 / 在生产环境中使用（"生产"在中文第一反应是工厂制造，"production"在软件语境=生产环境/真实业务） |
| `over time`（伴随积累含义） | 时间推移 | 在时间里 | 随时间 / 日复一日 / 持续运行后（"在时间里"是英文介词框架直译，中文用"随时间"或动词结构如"跑了上万次之后"） |
| `deep + software/tech` | 软件/技术 | 深度软件 / 深度技术 | 深耕 / 做到足够深 / 足够复杂（中文软件没有"深浅"隐喻；"deep"在此=复杂/扎实/需要深耕，改动词结构而非形容词+名词） |
| `X's extension / X's arm`（组织权力关系，如"OpenAI 的延伸"） | 组织/权力关系 | X 的延伸 | X 在背后扶持的代理人 / X 的外围势力 / X 变相推动的政治工具。"延伸"在中文锚定物理/空间域（道路的延伸、山脉的延伸），描述组织间权力关系时语义空洞——读者不知道是部门延伸、资金延伸还是业务延伸。必须补全权力关系动词：谁对谁做了什么？ |
| `partially + V` | 二值动词 | 部分卸载 | 动词本身含粒度 |
| `N/A` | 固定搭配拆解 | 双头格局（←双头垄断）| 两强并立 |
| `N/A` | 物理动词+抽象数字 | 从300亿拉到470亿 | 从300亿增至470亿 |
| 固定搭配拆解重组 | 从合法复合词中剥离语素 | 双头格局（←双头垄断）| 两强并立（中文语素≠英文 free morpheme） |
| `搭 + 抽象流程/机制`（如 handoff/审批/审查） | 流程/机制 | 搭交接 / 搭审查 / 搭流程 | 配置交接流程 / 搭建交接机制 / 写交接逻辑。`搭` 在中文语义锚点是实体架构（搭系统/搭框架/搭积木），不能搭配抽象流程名词。`不想手工搭交接？`→`不想手动配置交接流程？` |
| `drive + 抽象概念`（如 `drive a bet`） | 驱动/推进一个赌注/假设 | 驱动赌注 | 验证赌注 / 为赌注加码。"驱动"在中文锚点是被驱动物发生位移（驱动增长/变革），"赌注"不能被驱动——你只能为赌注加码，或验证赌注是否成立。`driving this bet`→"为验证这个赌注而倾注心血"，不写"驱动这个赌注" |
| `ball is in X's court / ball to X`（体育隐喻，如"球交给 Reviewer"） | 决策/审批语境 | 球交给 X / 球在 X 那边 | 把决断权交给 X / 把问题抛给 X。英文 `ball is in someone's court` 是通用隐喻，中文"球交给某人"携带随意/游戏感，技术审查/裁决语境不匹配。"测试挂了→球交给 Reviewer"→"测试挂了→把决断权交给 Reviewer" |

### 文化隐喻与制度概念的"外挂释义"原则

当原文的隐喻或制度概念在中文读者脑中没有对应锚点时，**不得简单直译，也不得完全抛弃意译**。必须采用"保留原词 + 补充中文锚定词"的策略，让读者在首次接触时即理解其含义和重要性。

**隐喻类**（保留意象 + 商业定语）：

| 原文隐喻 | ❌ 直译 | ❌ 抛弃 | ✅ 外挂释义 |
|:---|:---|:---|:---|
| `Yellow Brick Road` | 黄砖路 | 大厂主干道 | **巨头铺好的**"黄砖路" |
| `Rest of Oz` | 奥兹国其余地带 | 垂直细分赛道 | **深入特定行业的**"奥兹国其余地带" |
| `the Wizard`（指代大实验室） | 巫师 | 大实验室 | **掌控模型的**"巫师"（指大实验室） |

**制度/文化概念类**（保留原名 + 功能锚定词）：

| 原文概念 | 问题 | ✅ 外挂释义 |
|:---|:---|:---|
| `PAC / Political Action Committee` | 中文读者不知道 PAC 是集资工具，无法理解"没有 PAC"为什么是值得报道的立场 | **政治行动委员会（PAC，即美国用于合法筹集政治捐款的"钱袋子"机构）**。必须补一句功能锚定（"钱袋子/撒钱/利益输送"类词），否则"没有 PAC"在读者眼里只是句废话 |
| `Super PAC` | 同上，且比普通 PAC 更凶猛——可无限额接受捐款 | **"超级 PAC"**——首次出现时暗示其无上限属性 |
| `pod`（Spotify/硅谷组织模型，指小型跨职能自组织团队） | 中文互联网公司不普及，多数读者无对应体感 | **pod（小型跨职能团队）**——首次出现括号锚定，后文可裸用 |
| `501(c)(3) / 501(c)(4)` 等美国税法条款 | 中文读者完全无感 | 首次出现必须用括号补功能锚定，如"501(c)(4)（可匿名接受捐款的社会福利组织）" |

**规则**（隐喻类和制度类通用）：
- 首次出现时在原词后紧接括号锚定，4-12 字，不破坏原文节奏
- 锚定词必须揭示该概念在原文语境中的**核心功能或争议点**——不是词典定义，是"这篇文章为什么提到它"
- 后文可逐步减省锚定，因为读者已被桥接
- 如果这个概念在文章中反复出现且每次都承载不同含义，只在首次锚定即可

## 原则 C：密度对齐 — 模式速查

| 触发条件 | 操作 |
|:---|:---|
| 单句"的"≥3 次 | 拆为 2-3 个独立短句 |
| 主语-谓语 ≥15 字 | 修饰前置太长 → 调语序或拆分 |
| ≥2 层 `which/that/where` 嵌套 | 拆为独立短句，用"这/该机制"回指 |
| `A that does B by doing C through D` | 倒序：`A 通过 D 完成 C，从而实现 B` |
| 英文被动语态 | 转中文主动表述；删冗余"被/进行/作出/加以" |

## 硬事实检查（不可由原则推导）

| 检查项 | 方法 |
|:---|:---|
| 数字完整性 | 原文/译文数字计数对比，差值 ≤ max(2, 5%) |
| 代码块原样保留 | 代码块/Prompt/API/CLI 不得翻译、清洗、重排、补全 |

| 代码块语言标签 | 起始 fence 标注语言类型（如 ` ```json`） |

### 忠实翻译微调模式（`产出形态=忠实翻译` 适用）

> **边界**：1-3 词局部调整，不改语义；事实/数字/立场/因果方向完全保留

| 英文原文 | 字字对应（不通顺） | 允许的微调 |
|---|---|---|
| `delegate a share of X to Y` | 把 X 中越来越大的份额交给 Y | 把越来越大的 X 工作交由 Y 来完成 |
| `X is done by Y` | X 由 Y 完成 | Y 来完成 X |
| `X makes Y faster` | X 让 Y 越跑越快 | 我们的 Y 越跑越快（X 隐去） |
| `a growing share of` | 越来越大的份额 | 越来越多 / 越来越大的那一部分 |
| `Y itself` | Y 自身 | Y 本来（去"身"留"自"）/ Y 自己 |
| `X is accelerating Y` | X 正在加速 Y | Y 越跑越快（动词具象化） |
| `we delegate ... to AI` | 我们把...委托给 AI | 我们把...交由 AI 来做（动宾搭配优化） |
| `the length of tasks that ...` | 任务时长 | 以人类完成同等任务**所需时间**衡量的工作量 |
| `merge to the codebase` | 合并到代码库 | **合入**代码库 |
| `X per quarter` | 每个季度合并 X | **每季度合入** X |
| `a full recursive self-improvement` | 完整的递归自我改进 | **彻底的**递归自我改进 |
| `may increase the risks of X` | 可能**会增大** X 的风险 | 可能**让** X 的风险**陡增** |
| `... is becoming important` | ...变得重要 | ...变得**前所未有的**重要/**紧迫** |
| `more than ever` | 比以前更多 | **比从前**快了一个**数量级**（动 + 量级更具体） |
| `the impact of X` | X 的影响 | X **带来**的影响（动宾化） |
| `in the future, ...` | 未来，... | **未来...或**...（"或"表可能） |
| `play a key role` | 扮演关键角色 | **至关重要** / 起到**关键作用** |
| `... has a profound impact on Y` | ...对 Y 有深远影响 | ...**让** Y **发生**深远变化 |
| `... makes it possible to ...` | ...使...成为可能 | ...让...变得**可行** / ...有望实现... |
| `a significant portion of` | 相当大比例的 | **相当一部分** / **超过 X%** |
| `X has been ... for Y months` | X 已经 Y 个月了 | X **已持续** Y 个月 |
| `aim to ...` | 旨在... | **目标是**... / **力争**... |

**⚠️ 全面应用原则**（来自 v1→v2 对比的教训）：上表 22 条微调**应默认应用到全文每个句子**，不只是用户点出的几处。**微调的字数差异**通常为原文 5-10%，但**信息密度**显著提升。
