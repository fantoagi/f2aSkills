# v2 编辑技术预审（Editor Technical Gate）

## 定位

这是内容正确性和技术可信度门禁，不是风格润色。它承接旧版
`references/editor-technical-gate.md` 的六类检查，但改用 v2 的 G2/G3/G5 语言。

## v2 闸门映射

| 检查项 | v2 闸门 | 等级 |
|---|---|---|
| 正文口语词 | G5 | WARNING；按 A/B/C/D 和发布场景判断 |
| 指代与逻辑 | G3 | 唯一指代失败、因果方向错、起点逻辑错为 BLOCKER |
| 技术机制 | G2 + G5 | 对象、前置条件、动作描述不准确为 BLOCKER |
| 渲染等价性 | G5 | 公众号不支持的 LaTeX、裸 HTML、代码/图片渲染错误为 BLOCKER |
| 概念与术语 | G5 | 同一概念语义漂移为 BLOCKER；双语补注不足通常 WARNING |
| 品牌与大小写 | G5 | 同语境混用为 BLOCKER；标题式和正文式合法双轨为 WARNING 或通过 |

## 执行顺序

在正文初稿和最终标题生成后执行；应在所有语言润色完成后执行，避免后续润色改变待核查对象。

```text
C2 机械扫描
  → 语言/风格润色
  → Editor Technical Gate
  → claims lint / reader value check
  → 最终聚合到 stage-06-audit.md
```

## 人工必查项

### 1. 指代和逻辑

逐句回答：

- “它/这/那/这些/这种”是否只有一个可回指对象？
- “变回/重新/恢复”描述的起点是否真实存在？
- 因果关系是否来自材料或已登记推断？
- 动作的施事者、对象和结果是否明确？

### 2. 技术机制

对每个产品、工具、架构和数据流句子还原：

```text
对象 + 前置条件 + 动作 + 可观察结果
```

如果无法复现，回到原文、产品文档或一手来源核验。不得把“没有写权限”泛化成“不能改文件”，也不得把作者推断写成产品行为。

### 3. 渲染

重点检查：

- `$...$`、`$$...$$` 和残留 LaTeX 命令
- 裸 HTML、MathML 和 iframe
- 图片路径和替代文本
- 代码围栏、反引号和表格结构
- 公众号目标环境下的链接和公式显示

### 4. 概念与术语

盘点中文自造的角色词、状态词和概念名；同一概念统一用词，英文术语首次出现时按 glossary 规则补双语锚点。

### 5. 品牌与大小写

区分书名/标题式和正文普通引用式。只有同一语境中的大小写不一致才阻塞，合法的标题式 `AI-Native` 与正文式 `AI-native` 不应被误判。

## 审计输出

在 `runlog/<topic>/stage-06-audit.md` 记录。为保证机械检查稳定，产线审计必须使用下面的七字段 bullet 格式；如果为了人工阅读使用 `①`–`⑦` 编号或 `===` 分隔块，七个字段名仍必须保持不变；字段名只能使用下列规范键名，`technical_gate_lint.py` 兼容这两种字段前缀：

```markdown
### Editor Technical Gate

- 指代与逻辑：通过 / BLOCKER（位置：）
- 技术机制：通过 / BLOCKER（位置、核验来源：）
- 渲染等价性：通过 / BLOCKER（位置：）
- 概念与术语：通过 / WARNING（统一方案：）
- 品牌与大小写：通过 / WARNING（语境裁决：）
- 正文口语词：保留 / 改写 / WARNING（按模式说明理由）
- 聚合结果：通过 / 通过但有警告 / 未通过
```

不能用“已检查”代替逐项裁决；②指代逻辑和③技术机制任一 BLOCKER 未修复，不得交付。`=== 编辑技术预审 ===` 只能作为视觉分隔，不能替代七个可解析字段。
