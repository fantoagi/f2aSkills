# v2 C4 立场闸门（Stance Gate）

## 目的

C4 不是要求作者机械添加一句“我的观点”，而是在允许作者表达立场的模式中，
在大纲和正文之前生成一条可承担、可追溯、与源材料区分开的作者判断，避免文章退化为高质量转载。

## 适用矩阵

| 子模式 | C4 | 规则 |
|---|---|---|
| A-explainer | 强制 | 对“为什么值得关注/采用”给出一条有取舍的判断 |
| B-news | N/A | 事实快讯不新增作者立场，可保留事实本身的张力 |
| B-analysis | 强制 | 必须明确区分事实、源材料观点和作者判断 |
| C-faithful | 禁止 | 不新增作者立场；只保留原文已有立场 |
| C-retelling | 弱化 | 可有编辑选择和解释，不写独立判断；若用户提供判断，转 C-commentary |
| C-commentary | 强制 | 必须有区别于源作者的作者判断 |
| D-reading | 条件强制 | 只能使用用户明确提供的阅读观察；没有观察则声明缺失，不得代写经历 |
| D-learning | 强制 | 立场必须来自“旧认知→新认知”的真实变化 |
| D-practice | 强制 | 立场必须来自用户提供的版本、步骤、结果或失败记录 |
| R1/R2 | 跳过 | 不改变原稿立场 |
| R3 | 重新审查 | 触及观点和证据时重新生成/确认立场 |
| R4 | 跳过 | 事实纠错不自动改变立场 |

## 执行时序

```text
源材料与 Brief
  → 模式判断
  → C4 立场预热
  → 主张账本与大纲
  → 正文初稿
```

写作前只确定临时角度，不锁死最终标题；立场用于塑造角度和结构，而不是成稿后补丁。

## 独立立场生成

对 A-explainer、B-analysis、C-commentary、D-learning、D-practice，优先使用独立 stance subagent，
不要让主 Agent 在同一上下文里顺手填“我的判断”。独立 Agent 必须被明确授权：**可以不同意源材料**。

如果当前环境无法使用独立 stance subagent，主 Agent 必须先停止正文写作，切换到“隔离草稿”步骤：在独立的 Stance Seed 文档中完成四项输出，再回到主稿；不得把 Brief 的“作者判断”字段当作 C4 的充分替代。

输入：

- 源材料核心事实和限制
- Editorial Brief
- 临时角度
- 目标子模式

输出四项：

```markdown
## Stance Seed

1. 原文/材料的结论（别人说的）：
2. 我要补充、反对或意外的一点（我的原创判断）：
3. 这跟目标读者有什么关系：
4. 立场落点：开篇 / 第 X 节 / 结尾收束；一句或两句
```

## 边界

允许：

- 对已有事实进行评价、排序、加权和取舍
- 指出自己不同意、保留或意外的地方
- 将已有事实联系到具体读者、岗位和场景

禁止：

- 新增源材料没有的数字、事实或因果
- 把不确定性写成必然
- 把源作者观点改写成作者自己的事实判断
- 用第一人称伪造用户没有提供的经历、时间、数据或实测
- 用“其实/实际上”把作者推断伪装成客观事实

## 正文落地与保护

适用 C4 的文章必须把第 2、3 项中的有效内容落进正文；只写在内部 Stance Seed 不算完成。机械重叠只作落地预检，不是语义裁判：明显没有落地才阻塞，经过锐化或同义改写的立场必须交人工确认。
落点通常是开篇钩子、核心章节或结尾收束，但不能焊接进未经标注的源材料事实句。

后续润色允许改善措辞，不得：

- 删除第一人称承诺或保留意见
- 删除限制条件
- 把作者判断改成源材料观点
- 添加账本没有的新事实

## 交付闸门

- C4 适用且 Stance Seed 缺失：BLOCKER
- Stance Seed 存在但未落进正文：BLOCKER；若只是大幅同义改写导致机械重叠偏低，先发 WARNING 交人工确认，不因字面变化直接误杀
- C4 禁止的子模式新增作者判断：BLOCKER
- 判断包含未登记数字/事实：交由 G2 / claims_lint 阻塞
- 只有“这很重要/值得关注”一类无取舍判断：WARNING，要求重写

机械检查：

```bash
python scripts/stance_lint.py <article.md> --stance <stance.md> --mode C-commentary
```

完整结果写入 `runlog/<topic>/stage-06-audit.md`；High-risk 任务应同时保留 Stance Seed 作为内部记录。
